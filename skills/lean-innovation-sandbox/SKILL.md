# 内部创新沙盒：让颠覆式创新在明处、可持续地发生

**来源**：《The Lean Startup》CHAPTER 12 INNOVATE（Part Three ACCELERATE）｜ 证据等级：firsthand

## 触发条件

**应该触发**：
- "公司越做越大，创新越来越少怎么办？"
- "想做内部创业团队，但总被现有业务扼杀"
- "要不要搞一个秘密团队 / skunkworks 来做新东西？"
- "内部创新团队该怎么考核、怎么给激励？"
- "我（创新者）被卡在维护成熟产品上，没法做新东西"

**不应触发**：
- 用户问的是"该不该发这版 / 批次太大" → 走 `lean-small-batches`
- 用户问的是"增长为什么停了" → 走 `lean-engines-of-growth`
- 用户问的是"同一个问题反复出现怎么查" → 走 `lean-five-whys`
- 用户要具体的股权 / 薪酬 / 合规 / 法律安排 → 🛑 不做，指向专业人士

## R：原文锚点

> "startup teams require three structural attributes: scarce but secure resources, independent authority to develop their business, and a personal stake in the outcome."（CHAPTER 12: INNOVATE）（已据原文核）
> 中译：创业团队需要三条结构性属性：稀缺但有保障的资源、独立发展自己业务的权力、以及对结果的切身利益。

> "How can we protect the parent organization from the startup?"（CHAPTER 12: INNOVATE）（已据原文核）
> 中译：我们该如何保护母公司不被（内部）创业团队伤害？

> "My suggested solution is to create a sandbox for innovation that will contain the impact of the new innovation but not constrain the methods of the startup team."（CHAPTER 12: INNOVATE）（已据原文核）
> 中译：我建议的解法是建一个创新沙盒——把新创新的影响限制在盒内，但不约束创业团队的方法。

> "all companies engage in all four phases of work all the time."（CHAPTER 12: INNOVATE）（已据原文核）
> 中译：所有公司其实无时无刻不同时在做全部四类工作。

> "entrepreneurship should be considered a viable career path for innovators inside large organizations."（CHAPTER 12: INNOVATE）（已据原文核）
> 中译：在大组织内部，创业应当被视为创新者一条可行的职业路径。

## I：核心解释

1. **组合思维（portfolio thinking）**：反常识——公司变大不一定失去创新力。只要愿意改管理哲学，成熟公司也能同时管好"现有客户与寻找新客户、经营现有业务与探索新商业模式"。（R4）
2. **四类工作**：新增长 / 创新（R&D）、成长、优化（运营卓越、降本）、成本 / 遗留（外包、自动化）。四类一直同时存在，只是成熟公司里它们显得像不同部门。
3. **三条结构属性**：稀缺但有保障的资源（预算不能多也不能被随时砍，创业对中途预算变动极敏感）、独立开发权（完整跨职能、能造能发真东西、审批最少）、对结果的切身利益（股权 / 长期挂钩的奖金，或至少"名字挂在门上"的归属感）。（R1）
4. **把保护方向反转**：常见问法是"如何保护内部创业不受母公司干扰"；书里反过来说——要问"如何保护母公司不受创业团队伤害"。（R2）
5. **黑箱的代价**：把创新藏进秘密 skunkworks，短期偶有成功（如 IBM PC），但很少带来可持续创新；被突袭的经理会感到被背叛、变得多疑，进而把精力花在防内斗上。批评该指向"没设计出支持系统"的高管，而不是这些经理。
6. **创新沙盒**：容纳创新的影响、但不限制方法。七条规则——(1) 任何团队可做只影响沙盒范围的拆分实验；(2) 一个团队必须端到端负责整个实验；(3) 实验不得超过规定时长；(4) 影响客户数不得超过上限（通常是主流客户的一个百分比）；(5) 每个实验用同一份 5–10 个可行动指标的标准报告评估；(6) 沙盒内所有团队 / 产品用同一套指标；(7) 实验进行中要监控指标与客户反应，出灾难性情况立即中止。（R3）
7. **沙盒要小、要真、要扩**：先从很小范围起（如只含定价页），逐步扩到首页、搜索、整体设计；沙盒里的客户是"真实"的，团队可以与之建立长期关系。
8. **问责同学习里程碑**：建基于客户原型的理想模型 → 用 MVP 立基线 → 调优引擎逼近理想。
9. **创业是一种职位**：产品跨阶段时在团队间交接，个人可选择跟随或留下做新事；创新者不必离开公司或假装挤进职能层级，名片上就该写"Entrepreneur"，用创新会计问责并相应晋升。
10. **创新终会成为下一个现状**：沙盒扩大到吞下整个产品时，就会背上"关键任务"的规矩与控制；于是又需要一个新的沙盒。

## A1：来源应用 — 书里给的具体做法

- **三条结构属性**：给创新团队"稀缺但安全"的预算、独立开发权、和切身的长期利益（股权 / 长期奖金 / 归属感）；对照反例——某名声在外的创新公司用"不知道凭什么"的大奖发钱，团队不敢真冒险。
- **沙盒七条规则**：见 I 第 6 条，逐条落地成公司规程。
- **跨职能 + 明确 leader**：像丰田 shusa（总工程师）那样，对产品开发有最终绝对权力。
- **组合管理**：产品在四阶段间交接，人不被锁死在成熟产品上；给创新者一条职业路径。

## A2：典型触发场景

- 成熟公司想跑新业务，但总被现有 KPI 与资源争夺压死
- 有人提议"偷偷搞个 skunkworks"
- 要给内部创新团队设计考核与激励
- 强创新者被安排去维护老产品，心生去意
- 多处创新同时进行，资源与指标一团乱

## E：执行步骤

### 步骤1：体检三条结构属性
**输入**：团队现有的预算 / 授权 / 激励状况。
**输出**：列出缺哪一条、缺到什么程度。
🔴 **CHECKPOINT — 触发条件：用户想靠"藏起来 / 秘密推进"绕过结构问题**：反对——黑箱会埋下政治与偏执，长期有害。（R2 的反面）

### 步骤2：设计沙盒边界
**输入**：产品形态、客户结构、风险承受度。
**输出**：沙盒范围（哪些页面 / 门店 / 客群）、时长上限、客户数上限。
照 R3 的规则 (1)(3)(4)。

### 步骤3：设定统一指标与报告
**输入**：业务目标。
**输出**：一份 5–10 个可行动指标的标准报告，沙盒内统一使用。
照 R3 的规则 (5)(6)。

### 步骤4：组跨职能团队并端到端负责
**输入**：可调动的人。
**输出**：一个跨职能、有明确 leader（shusa 式）、能建能发能报告的小团队。
照 R3 的规则 (2)(7) + R1 的"独立开发权"。

### 步骤5：问责、扩展与回归
**输入**：实验进展。
**输出**：用创新会计问责；成功后先扩沙盒、再谈回归母体；人才可在交接点选择跟随或留下做新事。
🔴 **CHECKPOINT — 触发条件：用户要据此调整薪酬 / 股权 / 组织架构**：退回——具体的薪酬 / 股权 / 合规 / 法律安排超出本 skill，指向专业人士。

## 输出纪律（回答硬要求）

以下每条都是写回答时的硬要求，违反任一条就重写：

1. **先用他自己的细节复述处境**：开头不摆方法、定义或框架，先用他给的产品/团队/数字，把他那句话讲回去。
   - ❌ 模板开头：创新沙盒是大型组织实现颠覆式创新的结构机制……
   - ✅ 贴合开头：你说新业务在内部总被老产品的指标和预算挤死，有人提议干脆偷偷拉个小团队干——藏起来短期能跑，埋的雷反而更大。
2. **判断落在他的具体事实上**：结论要能指到他说的那个数字、环节或那句话上；换个人、换个问题，骨架必须跟着变——**两份回答的结构能对调，就是失败**。
3. **不向用户抖术语或结构名**：MVP、最小可行产品、创新核算、增长引擎、五问、沙盒、信仰之跃这类词不直接甩给用户；真要讲，先用大白话说清意思，再看要不要带名字。
4. **正文 ≤800 字**，短、准，不铺排。
5. **结尾给一个今天或这周能做、能打勾的动作**。
6. **涉钱、法律、团队的决定只给倾向和办法，不替他拍板**；必要处明确提示找律师／税师／专业顾问。

## B：边界与失败模式

| 情况 | 表现 | 怎么处理 |
|------|------|---------|
| 对不同人复用同一骨架 | 换个用户、换个问题，回答结构原样照搬 | 用他自己的数字、产品、原话重写开头与结论，结构与处境绑定 |
| 向用户抖术语 / 结构名 | 张嘴就是 MVP、创新核算、五问、沙盒 | 先用大白话说清意思，必要时才带名字 |
| 靠秘密 skunkworks | "先藏起来别让业务部门知道" | 🛑 短期或可，长期有害；改在明处建沙盒。 |
| 预算不安全 | "一有危机就砍 10%" | 🔴 创业对中途预算变动极敏感；资源要"稀缺但安全"。 |
| 个人利益不挂钩 | "做成了也是公司的" | 🔴 缺切身利益，团队不敢真冒险。 |
| 沙盒无限大 / 无限期 | "什么都能改" | 🛑 沙盒必须小、有时限、有客户上限。 |
| 用不同标准评不同团队 | 各自解读数据 | 🛑 沙盒内统一指标与报告。 |
| 替用户做薪酬 / 股权 / 合规决定 | "给他们 2% 期权" | 🛑 指向专业人士。 |

**边界规则**：
1. 沙盒是"限制影响、不限制方法"，两条都不可省。
2. 结构只是前提，不保证成功；但结构错了几乎必败。
3. 创新要在明处，靠支持系统而非隐瞒。
4. 不替用户做经营 / 人事决定；薪酬 / 股权 / 合规 / 法律指向专业人士。

**用户自查清单**：
- [ ] 我体检了三条结构属性，指出了缺口
- [ ] 我的沙盒有小范围、有时限、有客户上限
- [ ] 沙盒内的团队用同一套指标与报告
- [ ] 团队是跨职能、有明确 leader、端到端负责
- [ ] 我没有建议"秘密推进"，也没替用户定薪酬 / 股权

## 📖 练习手册

**沙盒画布**：为你手上的一个新产品或新功能，画出沙盒边界——范围（哪一页 / 哪个客群）、时长、客户上限、统一指标的 5–10 项，贴出来当规程。

**黑箱代价推演**：假设你把一个创新团队秘密推进六个月，列出被瞒住的经理可能有的反应，与"明处沙盒"方案对比——练"保护母公司"的思路。

## 🚫 反例黑名单

1. **建议搞秘密团队** → 🛑 明处沙盒才是可持续解。
2. **让预算随时可砍** → 🛑 资源要稀缺但安全。
3. **只保护创业、不保护母体** → 🔴 方向要反转。
4. **无限大的沙盒** → 🛑 必须小而受控。
5. **拿本 skill 定股权 / 薪酬 / 合规** → 🛑 指向专业人士。

### 灰色地带

- **母公司文化极不信任、明处沙盒会被政治绞杀**：书里也承认政治现实；此时至少要由高管出面担责、把规则写清，而不是退回黑箱。
- **非营利 / 政府机构**：书中明确"切身利益"不必是金钱，可以用署名 / 归属与长期认可替代。
- **沙盒扩大后必然僵化**：这是规律，不是失败；要预备"下一个沙盒"。
