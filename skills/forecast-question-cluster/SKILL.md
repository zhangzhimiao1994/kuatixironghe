# 问题聚类：把不可评分的大问题拆成一簇可评分的小问题

**来源**：《Superforecasting》第12章「What's Next?」（THE QUESTION THAT COUNTS / Question clustering to accelerate learning） | 证据等级：firsthand（"把这个概念真正做出来"是作者自陈的**未来研究设想**，见 R8，勿当作已验证结论）

## 触发条件

**应该触发**：
- 用户面对一个宏大而含糊的问题（"这场冲突会怎么收场""这个行业会变成什么样"），觉得无从下手
- 用户问"这种事根本没法量化，怎么办"
- 用户想为一堆相关的事件攒出可判对错的题目，形成可累计的判断
- 用户问"我到底该问什么问题""什么样的问题才是好问题"
- 用户想把一个长期战略关注点，转成一组可跟踪、可复盘的小指标

**不应触发**：
- 命题还没钉死、需要把事件与时间口径写清 → 先走 `forecast-calibrate-claim`
- 已有一道清晰命题要估概率 → `forecast-fermi-baserate`
- 判断某道题值不值得花力气（太易 / 太难）→ `forecast-triage-question`
- 给一批预测记分、比较准确度 → `forecast-keep-score`
- 纯事实查询或算术 → 直接做

## I：核心解释

1. **核心两难**：真正要紧的是那个大问题，但大问题**无法评分**；能评分的是小问题，可小问题又显得不要紧。赛事就是选了这个"不要紧但能判分"的一边。（R1）
2. **出路是"拆"**："这一切最后会怎样"这样的大问题，其内部**由许多小问题组成**。"北朝鲜会试射火箭吗？会再搞核试验吗？会拒绝核谈吗？会炮击南韩吗？"——每个小问题只给一点点洞察。（R2）
3. **答案是累计的**：小问题不必一个个都命中大问题，但它们的答案**可以累加**——"是"越多，大问题越可能落到"这会收场得很糟"。（R3）
4. **为什么叫"贝叶斯问题聚类"**：它和第7章讲的贝叶斯更新有亲缘关系——一个个小答案像一滴滴更新，逐渐把大问题的判断推向该去的地方。（R4）
5. **点彩画的比喻**：每点上一个小色点，单独看微不足道；点攒多了，图案就浮现出来——足够多的点能画出逼真的肖像或壮阔的风景。小问题就是这个"点"。（R5）
6. **好问题的标准**：好问题"让我们去思考一件值得思考的事"。它指向关键驱动因素，而不是表面热闹。（R6）
7. **拍脑门测试**：过一段时间回看这个问题，如果你拍着脑门说"我怎么早没想到这个！"——那它就是个好问题。书里的例子是 Friedman 2002 年问的那句"伊拉克之所以是今天的伊拉克，是因为萨达姆是萨达姆；还是萨达姆之所以是萨达姆，是因为伊拉克是伊拉克？"——它点到了日后撕裂伊拉克的关键（宗派主义），通过了测试。（R7）
8. **诚实标注边界**：作者自己说，把不可评分的大问题用"小问题簇"来回答，是**他未来要发展的研究方向**，还没被充分验证。别把"聚类一定能把大问题问出来"当成保证。（R8）
9. **问题本身就值得单独练**：书的结论是，好的判断力包含好几个维度，"会问好问题"是其中一个独立维度——它不能靠"我是好预测者"自动获得。（R9）

## A1：来源应用 — 书里怎么拆、怎么筛

1. **从一个真实大问题拆起（北韩案例）**：Paul Saffo 追问"这一切最后会怎样"这样的大问题；书里的做法是**回到构成它的近期事件**（试射、核试验、撕毁停战协定、网络攻击、切断热线），把大问题看成"许多小问题"的组合，再逐个问。（R2、R3）
2. **点彩式累计**：把每个"是/否"小问题的答案当作一个色点；色点越多，大问题的走向越清晰。不要把某一个点当成全部。（R5）
3. **拍脑门测试筛题**：拿一批候选问题，逐条问"过段时间回看，我会不会拍脑门说'早该想到'？"通不过的，要么太表面，要么不要紧。（R7）
4. **"这是问题，不是答案"的读法**：书里把 Friedman 的另一篇专栏（2014 年谈油价下跌的连锁后果）既当"含糊的预警"读、也当"提醒预测者该去关注什么的问题"读。作者说：超级预测者与"超级提问者"能力互补——前者提供校准好的答案，后者提供值得追的问题。（第12章 THE QUESTION THAT COUNTS）
5. **精确化是对付含糊的解药**：书里在谈如何让辩论可判时说——"结果必须是一个把歧义降到最低限度的预测问题"（"通胀多少？用什么基准衡量？多长时间内？"）。把大问题拆成小问题时，每一小问都要能回答这三样。（第12章 ONE LAST IDEA）

## A2：典型触发场景

- "这场仗 / 这场危机到底会怎么收场？"
- "这个行业十年后会变成什么样？"
- "我知道该关心，可我不知道该问什么问题。"
- "这些事根本没法打分，那研究它有什么意义？"
- 想给一个长期关注点建一套可跟踪、可复盘的小题目清单。

## E：执行步骤

### 步骤1：把大问题写下来，并承认它暂时不可评分

**输入**：`big_question`（用户的那句大问题）+ `scoring_goal`（他想拿它做什么）。
**输出**：一句写清的大问题 + 一句"它为什么不可评分"（太含糊、时间不明、口径不清）。

- 先别急着回答它。承认两难：要紧的无法评分，能评分的不要紧（R1）。这一步是把两难摆上台面。

🔴 **CHECKPOINT — 触发条件：用户坚持"你必须直接回答这个大问题"**：说明单句大问题因含糊而无法判对错——这正是书里"太含糊没法判断"的情形。把目标从"给一个答案"改成"建一簇能累计逼近它的题目"。

### 步骤2：拆成一簇可评分的小问题

**输入**：大问题 + `draft_subquestions`（若有）。
**输出**：一簇小问题，每条都**说清事件、时间、口径**，能判对错。

- 做法：回到构成大问题的**基础事件**，逐个转成"是/否"或"会发生什么"的可判题（R2）。
- 每条小问题都要能回答"多少？用什么基准？多长时间内？"（A1.5）。
- 让它像点彩：单点不重要，攒起来才成像（R5）。

🔴 **CHECKPOINT — 触发条件：拆出来的小问题仍然宏大、无法判对错**：退回重拆，或转 `forecast-calibrate-claim` 先把命题钉死。判不了对错的小问题，加再多也累计不出来。

### 步骤3：用拍脑门测试筛题

**输入**：步骤2 的小问题清单。
**输出**：通过 / 未通过的两栏，未通过的写下原因（太表面 / 不要紧 / 不可判）。

- 逐条问："过段时间回看，我会拍脑门说'早该想到'吗？"（R7）好问题应该"让我们去思考一件值得思考的事"（R6）。
- 别只留"好预测"的问题；"值得问"是另一个维度（R9）。

🔴 **CHECKPOINT — 触发条件：所有候选问题都通不过（没有一个让人拍脑门）**：这往往说明还没找到事件的**关键驱动因素**。先问"这件事真正由什么驱动"，再从驱动因素出发重新生成小问题。

### 步骤4：逐题判分，读累计趋势

**输入**：通过筛选的小问题 + `existing_answers`（已知答案）。
**输出**：每条小问题的判断（概率或是/否）+ 一句大问题的**累计走向**（"是"越多越偏某个方向）。

- 记住答案是可累计的："是"越多，大问题越倾向某一边（R3）。
- 每条小问题都可单独判分、单独复盘（见 `forecast-keep-score`），这正是它相对大问题的好处。

🔴 **CHECKPOINT — 触发条件：用户想用一个"是"就断定大问题**：喊停。单点只是点彩里的一滴；大问题的判断要靠**许多点的图案**，不是任何单独一点。

### 步骤5：如实标注这套聚类的能力边界

**输入**：本次聚类结果 + `time_horizon`。
**输出**：一句诚实的话——这套小题能逼近到什么程度、哪里还只是设想。

- 明说：用小问题簇回答大问题，是作者**尚待发展的设想**，不是已经验证的保证（R8）。
- 也提醒：它逼近的是"用许多可判的小答案拼出大走向"，不等于能预见大问题的确切结局。

## B：边界与失败模式

### 失败模式分支表

| 情况 | 表现信号 | 立即执行替代动作 |
|------|----------|------------------|
| 硬答大问题 | 抛开小问题，直接给一个宏大判断 | 🛑 回到步骤1，把两难摆出来；改为拆解 |
| 拆不动 | 小问题仍含糊、无法判对错 | 🛑 退回重拆或转 `forecast-calibrate-claim` |
| 问题没质量 | 候选题没有一条让人拍脑门 | 🛑 先找关键驱动因素，再重新生成问题（步骤2/3） |
| 以点代面 | 用一个"是"就断定大问题 | 🛑 提醒答案是可累计的，要许多点才成像 |
| 把设想当定论 | 宣称"聚类一定能回答大问题" | 🛑 明说这是作者待发展的设想（R8） |
| 问题越多越好 | 无限扩张题目清单 | 🛑 用拍脑门测试与驱动因素筛掉边角题 |
| 涉及就医 / 自伤 / 危机 | 大问题是"我还撑不撑得下去" | 🛑 放下框架，转专业资源与人的支持，不诊断 |

### 边界规则

1. **本 skill 只拆问题、不替用户下大结论**：它帮用户把大问题变成一簇可判题，最终读法由用户自己定。
2. **大问题不能靠拆解被"证明可答"**：拆解是逼近，不是解答（R1、R8）。
3. **每个小问题必须可判对错**：事件、时间、口径都要清楚。
4. **"好问题"是独立能力**：一名好预测者不一定就是好提问者，反之亦然；两者要互补，不必强求合一（R9）。
5. **不做投资 / 医疗 / 法律建议**。
6. **安全兜底**：当大问题指向就医、自伤或心理危机时，放下本框架，指向专业资源，不做诊断。

### 用户自查清单

- [ ] 我把那句大问题原样写了下来，并知道它为什么不可评分
- [ ] 我把它拆成了一簇可判对错的小问题（事件 / 时间 / 口径清楚）
- [ ] 我用拍脑门测试筛过题目质量
- [ ] 我的小问题指向关键驱动因素，而不是表面现象
- [ ] 我知道答案是累计的，没有用单点断定大问题
- [ ] 我如实说明了聚类能力本身的边界

**勾了 5 项以上**：问题聚类在正轨上。
**≤ 2 项**：多半还在硬答大问题、或没筛题目质量 → 回步骤1 或步骤3。

## 📖 练习手册

- **拆一个真问题**：挑一个你最近关心的大问题（"某冲突会怎么收场"），写出它背后 5–8 个可判对错的小问题，每条都补上时间与口径。
- **拍脑门回顾**：找三年前的一条新闻，问"当年该问什么问题，今天回看会让我拍脑门？"写下那个问题。
- **点彩累计**：给你拆出的小问题各判一个是/否（或概率），统计"是"的数量，写一句大问题的走向，并注明"这只是当前这批点"。
- **找驱动因素**：任选一个事件，问"它真正由什么驱动"，用驱动因素而不是表象，重新生成一组问题。

## 🚫 反例与黑名单

1. **直接宣称某个宏大预测就是大问题的答案** → 🛑 大问题暂时无法评分；先拆（R1）。
2. **把"是"的个数当成大问题的确证** → 🛑 答案是累计的、是概率式的走向，不是一次判定（R3）。
3. **留一堆含糊、无法判对错的小问题** → 🛑 不可判的问题加再多也累计不出来。
4. **用"我是好预测者，所以我问的问题自然好"** → 🛑 好提问是独立维度，需要单独练（R9）。
5. **宣称聚类已被证明能回答大问题** → 🛑 作者明说这是待发展的设想（R8）。
6. **把题目清单无限堆大** → 🛑 用拍脑门测试与驱动因素筛选；边角题会稀释注意力。
7. **在就医 / 危机语境里做题目拆解** → 🛑 停，转专业资源。

### 灰色地带（需谨慎判断）

8. **大问题里有一部分也许本就可预测**（如某个临近的具体事件）→ 可先把它单列出来当"可判题"，但这不改变其余部分的不可评分性；别因为抓住一个可判题就以为整个大问题可答。
9. **"值得问"与"可评分"冲突时怎么取舍** → 书里的立场是两者都要："值得问"保证方向对，"可评分"保证能被检验；若一条问题只能满足其一，优先保留"可评分"的作为骨架，把"值得问"的当作筛选方向。
10. **一个暧昧的"提醒"到底算问题还是算答案** → 书里示范：同一段话既可读成含糊的预警，也可读成"提醒你该去关注什么"的问题——取决于它能否催生可判的小问题。能催生的，就当问题用。
11. **作者自陈的设想与已验证结论的界限** → 凡涉及"聚类能否真的回答大问题"，一律标注为**待验证设想**；凡涉及"大问题由小问题构成""答案可累计"的机制阐述，可作 firsthand 主张使用。
