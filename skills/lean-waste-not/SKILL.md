# 不浪费：防止"精益创业"退化成伪科学

**来源**：《The Lean Startup》CHAPTER 13 EPILOGUE: WASTE NOT（Part Three ACCELERATE）｜ 证据等级：firsthand

## 触发条件

**应该触发**：
- "怎么避免我们把 MVP / pivot / 快速迭代做成口号或表演？"
- "团队拿着毛指标的高亮折线图说'看我们成功了'"
- "每次失败都说'我们学到了'，但看不出学到了什么"
- "出问题后大家讨论要不要放慢、加大预防 / 加大批次"
- "有人质疑'你凭什么说精益那套一定行'"

**不应触发**：
- 用户问的是"该多久发一版" → 走 `lean-small-batches`
- 用户问的是"增长为什么停了" → 走 `lean-engines-of-growth`
- 用户问的是"事故根因怎么查" → 走 `lean-five-whys`
- 用户问的是"内部创新团队怎么搭" → 走 `lean-innovation-sandbox`
- 用户要投资 / 上市 / 财务 / 法律建议（含长期证券交易所类主张） → 🛑 不做，指向专业人士

## R：原文锚点

> "The big question of our time is not Can it be built? but Should it be built?"（CHAPTER 13: EPILOGUE: WASTE NOT）（已据原文核）
> 中译：我们这个时代的大问题不是"它能不能被造出来"，而是"它该不该被造出来"。

> "There is surely nothing quite so useless as doing with great efficiency what should not be done at all."（CHAPTER 13: EPILOGUE: WASTE NOT，书中引 Peter Drucker）（已据原文核）
> 中译：没有什么比"把本不该做的事做得极其高效"更没用的了。

> "Anytime a team attempts to demonstrate cause and effect by placing highlights on a graph of gross metrics, it is engaging in pseudoscience."（CHAPTER 13: EPILOGUE: WASTE NOT）（已据原文核）
> 中译：任何时候，一个团队试图靠在毛指标曲线上高亮来证明因果，它就在搞伪科学。

> "Anytime a team attempts to justify its failures by resorting to learning as an excuse, it is engaged in pseudoscience as well."（CHAPTER 13: EPILOGUE: WASTE NOT）（已据原文核）
> 中译：任何时候，一个团队拿"学习"当借口为失败开脱，它同样在搞伪科学。

> "We cannot afford to have our success breed a new pseudoscience around pivots, MVPs, and the like."（CHAPTER 13: EPILOGUE: WASTE NOT）（已据原文核）
> 中译：我们不能让这场成功催生出围绕"转型""最小可行产品"之类的新伪科学。

## I：核心解释

1. **泰勒的百年回声**：1911 年泰勒《科学管理原理》提出"系统优先"与"工作可被研究改进"，但被后人简化为僵化手法（时间动作研究、差别计件、把人当自动机器）。精益制造纠正了它，却继承了其核心——工作可被科学地研究改进。
2. **当代的浪费来自做错的事**：21 世纪产能远超"知道该造什么"的能力，最大的浪费不是把事做得低效，而是"在做错的事，且是工业级的"。（R2）
3. **问题变了**：不再是"能不能造"，而是"该不该造"——未来繁荣取决于"集体想象力"的质量。（R1）
4. **伪科学的两种长相**：用毛指标高亮宣称因果；用"学习"为失败开脱。（R3、R4）
5. **别让成功催生新伪科学**：MVP、pivot 等一旦变成口号与仪式，就会重蹈科学管理被后人纠正的覆辙。（R5）
6. **科学 ≠ 公式、也不去人性**：泰勒原话的完整语境是"系统优先，但第一目标应是培养一流的人"；把他的意思读成"不需要优秀的人"是误读。
7. **变革会先变差再变好**：从职能卓越改到"验证性学习"，会暂时牺牲个体效率（专家被会议、交接、解释打断）——这是已知代价，可用理论预判并主动管理。
8. **用理论判断"特殊原因 vs 系统原因"**（Deming）：要能预测变更的结果，才能判断出问题是"真的是问题"还是新系统必经的阵痛。

## A1：来源应用 — 书里给的具体做法

- **用理论预测变更结果**：每一个改进建议，都问"理论能否预测它的结果？能否在小团队里孵化并观察？能否测量它的影响？"
- **把学习变成验证性学习**：如果一轮迭代真的学到了东西，下一轮就把它变成"可验证的学习"，而不只是口头声称。
- **诚实面对失败**：失败与挫折用诚实与学习回应，不用相互指责；不用"学习"当挡箭牌。
- **系统优先，但人也重要**：把改进建立在"研究如何把事做对"的严谨态度上，同时保留"愿景、敢冒险、在绝境中仍坚持的勇气"。
- **（书里的主张，非本 skill 建议）** 作者提出新研究计划与"长期证券交易所（LTSE）"等构想——本 skill 只如实转述为书中的观点，**不构成任何投资 / 上市 / 财务建议**。

## A2：典型触发场景

- 团队把 MVP / 敏捷 / 快速迭代挂在嘴上，却从不真的做实验
- 汇报里全是毛指标高亮折线，宣称"数据证明我们对了"
- 每次没做成都说"我们学到了"，但下一轮行为不变
- 一遇挫折就想"放慢、加大预防、回到大计划"
- 被问"你凭什么说这套一定行"，只会举别人的成功故事

## E：执行步骤

### 步骤1：区分"做错事"与"低效做事"
**输入**：团队当前在做的事。
**输出**：判断浪费是"效率问题"还是"方向问题"。
🔴 **CHECKPOINT — 触发条件：用户想靠"把事做得更高效 / 加班更多"来解决**：提醒——问题可能不在效率，而在"做的是不该做的事"。（R2）

### 步骤2：体检是否伪科学
**输入**：团队的汇报与论证方式。
**输出**：指出是否踩了 R3 / R4 的两条线。
🔴 **CHECKPOINT — 触发条件：用户否认 / 反驳时**：回到定义——"能不能重复地用产品改变你建模的客户行为？"能则是事实，不能就是故事。

### 步骤3：把"学习"转成下一轮可验证
**输入**：上一轮声称的"学到了"。
**输出**：一个下一轮可证伪的实验。
照 R3、R4：学习必须在下一轮变成"可验证的学习"。

### 步骤4：用理论预测变更结果
**输入**：一个想引入的流程变更（含"要不要放慢"）。
**输出**：对变更结果的预测 + 小范围孵化与测量方案。
🔴 **CHECKPOINT — 触发条件：用户想无脑"放慢 / 加大预防 / 加大批次"**：提醒——书中说"放慢、精细流程"多是世纪前的旧解法；先问它是否真的解决"做错事"。

### 步骤5：守住"系统优先，人也重要"
**输入**：变更中的情绪与文化。
**输出**：一份既不神化流程、也不忽视人的落地说明。
🔴 **CHECKPOINT — 触发条件：用户要据此做投资 / 上市 / 财务规划**：退回——不做投资 / 财务 / 法律建议。

## 输出纪律（回答硬要求）

以下每条都是写回答时的硬要求，违反任一条就重写：

1. **先用他自己的细节复述处境**：开头不摆方法、定义或框架，先用他给的产品/团队/数字，把他那句话讲回去。
   - ❌ 模板开头：精益的核心是区分"高效做错事"与"高效做对事"……
   - ✅ 贴合开头：你团队嘴上都在说"快速迭代"，可真要赌一个能被推翻的预测时谁都不肯下——这多半不是精益，是拿名词当行动。
2. **判断落在他的具体事实上**：结论要能指到他说的那个数字、环节或那句话上；换个人、换个问题，骨架必须跟着变——**两份回答的结构能对调，就是失败**。
3. **不向用户抖术语或结构名**：MVP、最小可行产品、创新核算、增长引擎、五问、沙盒、信仰之跃这类词不直接甩给用户；真要讲，先用大白话说清意思，再看要不要带名字。
4. **正文 ≤800 字**，短、准，不铺排。
5. **结尾给一个今天或这周能做、能打勾的动作**。
6. **涉钱、法律、团队的决定只给倾向和办法，不替他拍板**；必要处明确提示找律师／税师／专业顾问。

## B：边界与失败模式

| 情况 | 表现 | 怎么处理 |
|------|------|---------|
| 对不同人复用同一骨架 | 换个用户、换个问题，回答结构原样照搬 | 用他自己的数字、产品、原话重写开头与结论，结构与处境绑定 |
| 向用户抖术语 / 结构名 | 张嘴就是 MVP、创新核算、五问、沙盒 | 先用大白话说清意思，必要时才带名字 |
| MVP / pivot 变口号 | "我们敏捷，我们在 pivot" | 🛑 没有可验证实验就是伪科学。 |
| 毛指标高亮当因果 | "这条线在涨，是我们做的" | 🛑 用可行动指标与对照。 |
| 用"学习"为失败开脱 | "我们又学到很多" | 🛑 学习须在下一轮变成可验证的。 |
| 用"高效"掩盖做错事 | "我们效率很高" | 🔴 先问方向对不对。（R2） |
| 把精益读成"去人性" | "流程第一，人可替换" | 🛑 泰勒原话是"系统优先，也要培养一流的人"。 |
| 拿 LTSE 等当投资建议 | "快去买 LTSE 的股票" | 🛑 书中主张 ≠ 投资建议。 |

**边界规则**：
1. 本 skill 只做"反伪科学 / 反浪费"的体检，不做商业决策。
2. 不替用户做经营决定；不给投资 / 财务 / 法律建议。
3. "系统优先"不等于忽视人；"科学"不等于公式化或去人性。
4. 区分"特殊原因"与"系统原因"要借理论，不靠情绪。

**用户自查清单**：
- [ ] 我分清了"做错事"与"低效做事"
- [ ] 我指出了是否踩了毛指标因果 / 学习借口两条线
- [ ] 我把"学习"转成了下一轮可验证的东西
- [ ] 我用理论预判变更结果，而不是无脑放慢 / 加大
- [ ] 我没有把书里主张（如 LTSE）当投资建议

## 📖 练习手册

**伪科学体检**：翻出团队最近一次"成功汇报"，逐条问——"这是毛指标还是可行动指标？""我能不能重复地改变客户行为？""'学到'的东西下一轮会怎么验证？"

**放慢反思**：写下最近一次"想放慢 / 加大预防"的冲动，追问"这是特殊原因还是系统原因？我的理论预测什么？"——练"用理论而不是情绪做判断"。

## 🚫 反例黑名单

1. **把 MVP / pivot 当口号刷** → 🛑 无可验证实验即伪科学。
2. **毛指标高亮当因果证明** → 🛑 踩红线。
3. **"我们学到了"当免罪牌** → 🛑 学习须可验证。
4. **用"高效"掩饰"做错事"** → 🔴 先看方向。
5. **拿书中 LTSE 等主张当投资建议** → 🛑 不是投资建议。

### 灰色地带

- **用户确实在真转型期、情绪低落**：区分"真阵痛"与"真伪科学"需要理论；若一时难分，先如实说明"这是已知的过渡代价"，并要求下一轮的可验证证据。
- **书的立场很鲜明（如对放慢 / 加大预防的批评）**：转述时要标明这是作者的论点，不是放之四海的定论；对用户的具体处境保持中立。
- **"诚实面对失败"被读成"不必负责"**：诚实是为学习，不是免去担当；具体如何问责依组织制度，超出本 skill。
