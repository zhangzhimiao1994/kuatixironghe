# 毛泽东选集思维系统

> 毛泽东《毛泽东选集》第 1-5 卷 → 25 个可执行 skill
> evidence level: firsthand（原文蒸馏）

## 触发条件

**应该触发**（用户会怎么说话）：
- 面对多问题交织、需要判断主要矛盾或优先级（"问题太多不知道从哪下手""每个都很重要"）。
- 以弱对强、需要长期竞争节奏或不对称打法（"对手比我强太多""什么时候能翻盘"）。
- 方案推不下去、组织管理或团队纠偏（"方案一直推不下去""团队文化出问题了"）。
- 心态与行动力问题（"压力太大不敢行动""没准备好不敢开始""计划总被打乱"）。

**不应触发**（看起来像但其实不是）：
- 纯技术故障（代码 bug、服务器排障）→ 直接调试。
- 单一事实查询（天气、价格、时间）→ 直接回答。
- 紧急生命安全危机 → 立即行动或求助。
- 简单日常决策（"午餐吃什么"）与纯闲聊 → 简单决策或自然对话。

## R：原文锚点

> "不同质的矛盾，只有用不同质的方法才能解决。……用不同的方法去解决不同的矛盾，这是马克思列宁主义者必须严格地遵守的一个原则。"（《矛盾论》，1937年）（已据原文核）
> "研究任何过程，如果是存在着两个以上矛盾的复杂过程的话，就要用全力找出它的主要矛盾。捉住了这个主要矛盾，一切问题就迎刃而解了。"（《矛盾论》，1937年）（已据原文核）
> "没有调查，没有发言权。"（《反对本本主义》，1930年）（已据原文核）
> "研究问题，忌带主观性、片面性和表面性。"（《矛盾论》，1937年）（已据原文核）

（出处：以上均逐字引自本系统各子 skill 的 R 节，章名沿用其 source_chapter。路由的第一条依据就是"不同质的矛盾，只有用不同质的方法才能解决"——先定问题属于哪一类，再选对应打法。）

## I：核心解释（路由原理）

路由就是"先认清这是哪一类问题，再选对应的打法"。依据：不同质的矛盾要用不同质的方法解决；同类问题里先抓住主要矛盾；判断前先做调查，不带主观、片面、表面。

1. **先定性再选打法**：不定性就上手，等于用错药。先判断问题属于哪一层（认识论 / 调查 / 竞争 / 心态 / 组织管理）。
2. **一类问题一套方法**：不同质的矛盾用不同质的方法，25 个子 skill 就是 25 种方法。
3. **抓住主要矛盾再匹配**：多个问题交织时，先找主要矛盾，它决定该用哪个 skill。
4. **够复杂才用**：先过 3 秒检查（"够复杂吗？"），简单问题不激活本系统。
5. **路由不摊开**：回答里不展示路由表或子 skill 清单，需要时压成一句话。

## A1：来源应用（书里哪类问题归到哪类）

- **《矛盾论》(1937)**：多个问题交织、找不到根——归到「主要矛盾 / 矛盾特殊性」类，用矛盾分析法。
- **《实践论》(1937)**：想法没经实践检验、不知对不对——归到「实践认识论」类。
- **《反对本本主义》(1930) / 《农村调查》序言(1941)**：凭二手信息、坐在办公室拍板——归到「调查研究」类。
- **《论持久战》(1938)**：以弱对强、需要长期节奏——归到「持久战三阶段 / 战略藐视战术重视」类。
- **《关于领导方法的若干问题》(1943)**：方案推不下去、一般号召不落地——归到「一般号召个别指导 / 群众路线」类。
- **《党委会的工作方法》(1949)**：多任务忙不过来、不会"弹钢琴"——归到「弹钢琴 / 辩证平衡」类。

## A2：典型触发场景（哪类问题归到哪类）

1. "好几个问题交织在一起，我不知道根本矛盾在哪。" → 矛盾分析法。
2. "对手比我强太多，我该怎么打？" → 不对称战略 / 持久战三阶段。
3. "团队里几个人互相推诿，方案推不下去。" → 群众路线 / 两类矛盾 / 组织纠偏诊断。
4. "资源有限，不知道该往哪投。" → 集中优势兵力。
5. "没准备好，不敢开始。" → 在战争中学习战争。
6. "多任务忙不过来，计划总被打乱。" → 弹钢琴 / 主动性灵活性计划性。

## 使用原则

1. **自动路由**：说你的问题，系统自动匹配子 skill
2. **先诊断后行动**：先匹配子 skill 诊断，再给行动方案
3. **3 秒检查**：先自问"够复杂吗？"——不够就不用

## 输出纪律（只约束怎么呈现，不改方法本身）

1. **结论先行**：第一段就给出"这件事属于哪一类问题 + 你现在该怎么办"，一句话说清；依据放后面展开，不要把分析过程放在结论前面。
2. **路由不摊开**：不在回答里展示路由表、子技能清单或"命中/配套子技能"。需要时压缩成一句话，如"这套打法主要用三样东西：定性、调查研究、沟通"，让用户知道用了哪些角度即可。
3. **定性落到动作**：定性、分析和每条建议都要落到"用户明天做什么"上；收尾必须有一条可执行动作（谁、做什么、先做哪一步）。
4. **长度纪律**：常规问题不超过必要篇幅，只展开真正在用的框架，不把每个框架都完整讲一遍；用不上的不列。

## E：执行步骤（路由流程）

🔴 **CHECKPOINT：路由前先过 3 秒检查**——凡命中 NOT trigger 的（纯技术故障、单一事实查询、紧急危机、闲聊），不激活本系统，直接回答或直接处理。

- **输入**：用户原话（用户对问题的描述）与该问题的背景信息（涉及的任务、对手或合作者、可动用的资源与所在阶段等，都取自用户自己的说法）。
- **输出**：给用户看的一句话（说清这是哪一层问题、大概用哪几样打法，需要时可点出子 skill 名），结论先行；不在回答里展示路由表或子技能清单，等用户确认后再由选中的子 skill 给出方案。
- 路由先过 3 秒检查（够复杂吗？），只有通过检查的问题才进入匹配；路由本身不给方案，方案由选中的子 skill 给出。

## B：边界与失败模式（路由失败分支）

路由不保证一次到位。下面几类情况出现时，按表处理，处理完仍要回到 3 秒检查与匹配。

| 情况 | 表现 | 怎么办 |
|------|------|--------|
| 无匹配 | 问题够复杂，但 25 个子 skill 的触发场景都套不上 | 先追问一句，请用户点出最核心的矛盾或任务；仍无匹配就说明不在本系统覆盖范围，直接回答 |
| 两个都像 | 同一个问题同时命中两个子 skill | 说清两个方向各自解决的是哪一层问题，请用户确认更贴近哪个；若确实交织则组合使用，并指明先后 |
| 用户否认路由 | 用户回「不对，不是这个」 | 回到匹配，按用户修正重新路由；或请其说明想解决的是哪一个问题，改用对应子 skill |
| 命中后发现不适用 | 进入子 skill 后，它自己承认不适用于当前问题 | 停下这个子 skill，回到路由重选或改走组合，不硬套 |
| 命中 NOT trigger | 问题其实是纯技术故障/单一事实查询/紧急危机/闲聊 | 不激活本系统，按 CHECKPOINT 与反例清单直接回答或直接处理 |

## 练习手册

- **先定性再选打法**：拿一个真实问题，先写出"它属于哪一层（认识论/调查/竞争/心态/组织管理）"，再对照 25 目录选出对应子 skill，不看答案自查。
- **主要矛盾定位**：对一个问题写下你判断的主要矛盾，再问"抓住它，哪些问题会迎刃而解？"，检验这个矛盾是不是"上游因"。
- **结论先行改写**：把一次原来的分析式回答改写成"第一段给结论 + 一条可执行动作"的形态，其余压成一句话说明用了哪几样打法。

## 灰色地带

- **一个问题同时命中两个子 skill**：不硬选一个。说清两个方向各自解决哪一层问题，请用户确认更贴近哪个；确有多面则组合使用并指明先后。
- **问题"看着复杂、其实简单"**：3 秒检查若判为简单，不激活本系统，直接回答或直接决策。
- **用户否认路由**：按用户修正重新路由，或请其点出真正的核心矛盾/任务，不硬套原判断。
- **信息不足、连核心矛盾都点不出**：先追问一句请用户点出最核心的矛盾或任务；仍无匹配就说明不在覆盖范围，直接回答。

## 回答结构模板（结论 → 定性 → 动作）

1. **结论段（先给）**：这是【哪一类问题】，你现在先做——【一条具体动作】。
2. **定性**：为什么归到这一类：关键矛盾是……（一两句，取自用户自己的说法）。
3. **只展开真正在用的**：这套打法主要用【两三样东西，如定性、调查研究、沟通】，只把其中真正在用的那个讲透。
4. **收尾动作（必须有一条）**：明天/本周具体一步——谁、做什么、先做哪个、怎么算做成了。
