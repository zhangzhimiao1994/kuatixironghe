# 脏腑传变预测法 (Cascade Prediction)

> 本 skill 只提供身心与系统的预测视角，**不作医疗判断、不替代就医**；文中“五脏”“传变”等表述是系统分析的隐喻映射，不是医学诊断。

## 触发条件

**应该触发**：
- 某个部门/模块/组件出了问题，用户需要预测这个问题会沿着什么路径扩散，最终影响哪些环节。
- 用户知道某处出了问题，想在问题扩散之前提前加固下游环节。
- 系统已经发生了连锁崩溃，用户需要回溯问题的传播路径。
- 语言信号：“这个问题会不会引发其他问题？”“如果不处理会怎样？”“一处出问题，其他地方会不会跟着出事？”“需要提前在哪里布防？”“连锁反应/多米诺效应”“这个问题会扩散到什么范围？”。

**不应触发**：
- 孤立问题、不会产生连锁反应的场景。
- 各环节完全独立的松耦合系统。

## R：原文锚点

1. “五脏受气于其所生，传之于其所胜，气舍于其所生，死于其所不胜。”（《黄帝内经·素问》·据公版原文核·玉机真藏论篇第十九）

2. “病之且死，必先传行，至其所不胜，病乃死。”（《黄帝内经·素问》·据公版原文核·玉机真藏论篇第十九）

3. “五脏相通，移皆有次。五脏有病，则各传其所胜。”（《黄帝内经·素问》·据公版原文核·玉机真藏论篇第十九）

## I：核心解释

系统中的问题不会停留在原地——它会沿着固定的路径向外传播。
素问用五脏相克的链条来描述这个传播路径：
肝(木)→脾(土)→肾(水)→心(火)→肺(金)→肝(木)，
每个环节的问题都会传给“它所克”的下一个环节。

这个方法论的核心价值在于：问题不是随机扩散的，而是有方向、有次序的。
掌握了传播路径，就可以提前预判下一个受害的环节，在那里预先布防。

它包含三个关键操作：
第一，定位——当前问题出在哪个环节；
第二，画路径——按相克链推出问题的传播方向和顺序；
第三，设防——不等问题传到下一个环节，提前在那里加固。

这个思路迁移到任何有“环节A出问题会影响环节B”的系统都适用——
组织管理、供应链、技术架构、生态链条，只要能画出“谁影响谁”的传递路径，
就能用传变预测来防患于未然。

## A1：来源应用

### 案例 1: 五脏传变路径与时间预测
- **问题**: 五脏之病不治，会如何传变？何时会危及生命？
- **方法论的使用**: 素问给出了完整的传变路径：肝受气于心(木生火)→传之于脾(木克土)→气舍于肾(水生木)→至肺而死(金克木)。心、脾、肺、肾各有类似的链条。并且给出了传变的时间预估：“法三月，若六月，若三日，若六日”。
- **结论**: 传变有固定方向(所胜)和终点(所不胜)，预判了路径就可以在中间环节阻断。
- **结果**: 能预判疾病走向的医生(“上工”)可以在传变途中拦截，不能预判的(“下工”)只能被动应付。

### 案例 2: 外痹内传五脏
- **问题**: 风寒湿引起的痹症(外感)如何影响内脏？
- **方法论的使用**: 痹论指出：骨痹不已→内舍于肾，筋痹不已→内舍于肝，脉痹不已→内舍于心……外部的病邪沿着特定的对应关系逐步深入内脏。
- **结论**: 外部问题如果持续不解决，会按固定路径向深层传播——从功能层(筋骨脉肌皮)传到核心层(五脏)。
- **结果**: 提示必须在痹症尚在外层时就积极治疗，防止内传。

## A2：典型触发场景

### 用户会在什么情境下需要这个 skill?

1. **局部问题需评估全局影响**: 某个部门/模块/组件出了问题，用户需要预测这个问题会沿着什么路径扩散，最终影响哪些环节。
2. **预防性布防**: 用户知道某处出了问题，想在问题扩散之前提前加固下游环节，而不是等问题传到再仓促应对。


3. **复盘连锁故障**: 系统已经发生了连锁崩溃，用户需要回溯问题的传播路径，理解为什么A坏了最终导致Z也坏了。
   🛑 **STOP**：请确认上一步的分析结果后再继续。


### 语言信号 (用户的话里出现这些就应激活)

- “这个问题会不会引发其他问题？”
- “如果不处理会怎样？”
- “一处出问题，其他地方会不会跟着出事？”
- “需要提前在哪里布防？”
- “连锁反应/多米诺效应”
- “这个问题会扩散到什么范围？”

### 与相邻 skill 的区分

- 与 `context-adaptation` 的区别: 传变预测关注的是问题在时间维度上的扩散路径(下一步会怎样)，因地制宜关注的是问题在空间维度上的环境适配(换个地方怎么办)。前者是纵向预测，后者是横向适配。
- 与 `negative-feedback` 的区别: 传变预测是“问题沿着链条传播”，亢害承制是“某个力量过度亢盛需要引入制衡”。前者是线性传播，后者是过冲-回调。
- 关系: `five-elements-network`（depends-on）——传变路径(肝→脾→肾→心→肺→肝)直接来自五行相克链条，不理解生克关系就画不出正确的传变图。`prevention-strategy`（composes-with）——一个回答“问题会沿什么路径扩散”，一个回答“在路径上如何提前设防”，合起来即“预测传播→提前布防”。

## E：执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位当前问题所在的环节**
   - 将系统拆解为若干环节/模块/部门，确定问题当前出在哪一个环节。
   - 完成标准: 明确标注“当前问题位置”以及该环节的核心功能。
   - **输入**: 系统的环节划分与当前问题现象 → **输出**: 当前问题位置及该环节的核心功能。
   🔴 **CHECKPOINT**：把“当前问题位置”交用户确认，确认后再画传变路径。

2. **画出传变路径图(相克链)**
   - 梳理系统中各环节之间的“谁影响谁”关系，画出传递链条。
   - 从当前问题环节出发，沿传递方向逐级推导：问题会传到哪个环节？再下一个是哪个？
   - 标记每个环节的“承受能力”：哪些环节脆弱(容易传变)，哪些环节有缓冲(可能阻断传播)。
   - 完成标准: 产出一幅传变路径图，标注每一步的传播方向和预计影响时间。
   - 判停条件: 若系统各环节完全独立无传递关系，则不存在传变路径，此 skill 不适用。
   - **输入**: 步骤1 的问题位置 + 环节间的影响关系 → **输出**: 传变路径图（含传播方向与预计影响时间）。
   🔴 **CHECKPOINT**：展示传变路径图交用户确认；链路超过 3 站时重点关注前两站阻断，并强制检查有无反向/反馈环。

3. **在下一个环节提前布防**
   - 针对传变路径上的第一个下游环节，立即部署预防措施。
   - 同时评估：是否需要在更远的下游也预先加固。
   - 完成标准: 产出布防方案——在每个关键节点标注“预防措施”和“早期预警信号”。
   - **输入**: 步骤2 的传变路径图 → **输出**: 布防方案（每个关键节点的预防措施与早期预警信号）。
   🔴 **CHECKPOINT**：确认布防方案与预警信号后再输出；多条路径同时激活时按“到终点时间”排序，先堵最快到达关键子系统的。

## B：边界与失败模式

### 不要在以下情况使用此 skill

- **各环节完全独立的系统**: 如果模块A出问题不会影响模块B，就不存在传变路径，此方法无用武之地。
- **一次性事件不会引发连锁反应**: 如单个人员的偶尔失误，如果没有系统性传导机制，不需要画传变路径。

### 失败模式分支表

| 情况 | 表现 | 怎么处理 |
|------|------|---------|
| 不知传变次第就治疗 | 不了解传播规律 → 被动追着问题跑 | 先画传变路径图再设防。五脏相通移皆有次——不了解次第就无法预判 |
| 只治当前不管下游 | 头痛医头脚痛医脚 → 治好了这里那里又冒出来 | 处理任何问题时标注：这个问题会影响到谁？在哪里提前设防？ |
| 传变链路太长 | 链路超过 3 站 → 不确定性太高，投入产出比下降 | 重点关注前两站阻断。第二站设防最优策略——有缓冲时间又不至于太早浪费资源 |
| 多条传变同时激活不知优先 | 资源分散堵所有路径 → 都堵不住 | 按到终点的时间排序。哪个路径率先到达关键子系统 → 先堵哪个 |
| 固定传变路径忽略反馈环 | 素问的传变是线性的 → 现实有双向和反馈环 | 两步法：① 先按相克链列标准路径 ② 检查非标准连接（双向/反馈环）。永远问「这里会不会反过来影响」 |

### 作者在书中警告的失败模式

- 不知传变次第就治疗——素问说“五脏相通，移皆有次”，不了解传播规律就无法预判走向，只能被动追着问题跑。
- 只治当前环节不管下游——“头痛医头脚痛医脚”就是不知道传变的典型表现，问题是治好了这里那里又冒出来了。

### Fallback（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败 → 兜底 |
|---------|---------|-------------|
| 传变链路太长（>3站） | 重点关注前两站阻断。第三站后不确定性太高。第二站设防是最优策略 | 前两站都无法设防 → 回到第一站加固。如果源头守不住，后面都是白搭 |
| 多条传变路径同时激活 | 按「到终点时间」排序。哪个路径率先到达关键子系统 → 先堵哪个 | 全部都快到了 → 放弃逐一堵截。集中资源保护最核心的子系统，其他的接受一定损失 |
| 传变路径上某一站似乎被跳过 | 可能存在隐蔽传变——该站已有问题但未被观察到。回头检查被跳过的节点，确认真的没事 | 检查后确认没事 → 说明传变路径可能有跳跃。更新传变图为直达路线 |
| 只按固定相克路径画图，忽略反馈环 | 两步法：① 先按相克链画标准路径 ② 强制检查每个环节：「这里会不会反过来影响上游？」 | 反馈环太多 → 停止画线性的传变图，转用 `five-elements-network` 做网状分析 |
| 治好了当前站但下游更严重了 | 可能是「治病留邪」——表面治好了，问题转移了。回查当前站的传变方向，确认没有遗漏 | 下游问题持续加重 → 不是传变，是下游本身就有隐患被当前站的波动触发了。回归源头处理下游本来的问题 |
| 传变速度超过预期 | 重新评估传变时间。如果实际比预估快 2 倍以上 → 之前可能低估了耦合强度或存在加速器 | 速度失控 → 切换到应急模式。不在乎在哪一站设防了，全力保护最后一站（最关键的子系统） |

### 作者的盲点 / 时代局限

- 素问的传变路径是固定的(五行相克顺序)，而现实系统的传播路径往往是网络状的、多向的，甚至可能有反馈环。本 skill 分析路径的步骤: (1) 先按相克链列出标准路径; (2) 再检查是否存在非标准连接（双向、反馈环）; (3) 按影响力和发生概率排序所有可能路径。
- 古代没有量化工具，传变时间只能粗略估算(“三月/六月/三日/六日”)，现代可以结合数据分析做更精确的时间预测。

### 容易混淆的邻近方法论

- **“风险传播分析”**——现代风险管理中的传播分析通常是概率驱动的，传变预测法更强调“必然路径”和“结构化布防”，操作更简洁。
- **“根本原因分析(RCA)”**——RCA是回溯找根因(为什么出问题)，传变预测是前瞻看走向(问题会往哪里去)，方向相反但互补。

**安全兜底**：涉及身体、就医、用药或心理危机时，只做提醒与陪伴，**不作医疗判断、不替代就医**。

## 练习手册

1. **定位置**：把当下出问题的那一环写下来，标出它的核心功能。
2. **画路径**：从它出发，沿传递方向写出“传到谁→再传到谁”，标每一步的方向和预计时间；再强制检查有没有反向/反馈环。
3. **先设防**：针对第一个下游环节写一条预防措施和一条早期预警信号，并注明“为什么在这一站设防”。

> 本练习只用于练习连锁预测，不作医疗判断、不替代就医。

## 灰色地带

- **线性路径 vs 反馈环**：原书传变是线性的，现实常有多向与反馈环；反馈环过多时转网格分析（`five-elements-network`）。
- **“必然路径” vs 概率驱动**：传变预测强调必然路径与结构化布防，但现实中某些传播更像概率事件，需结合影响力与发生概率排序。
- **跳站现象**：某站似被跳过，可能是隐蔽传变（未观察到），也可能是路径本身有跳跃；先回查再决定。
- **源头 vs 下游**：治了当前站下游却更重，可能是“治病留邪”（问题转移），也可能是下游本就埋着隐患。
