# 黄帝内经身心系统

> 《黄帝内经》素问 + 灵枢 → 22 个可执行 skill
> evidence level: firsthand（原文蒸馏）

> 本系统是**路由型总入口**，只把问题归到某个子 skill，不产出行动方案；**不作医疗判断、不替代就医**。涉及紧急生命安全时，跳过路由，直接就医/急救。

## 触发条件

**应该触发**（问题分类）：
- 身心健康与系统调节
- 情绪管理与身心联动
- 季节适应与饮食平衡
- 问题预防与风险预测
- 个体差异与方案定制

触发词：身体、情绪、累、虚、上火、换季、饮食、失衡、阴阳、五行、气血、脏腑、经络、体质、未病。

**不应触发**（NOT trigger）：
- 纯技术问题（代码 bug、服务器故障）
- 简单问答（天气查询、价格查询）
- 紧急危机需立即行动
- 纯闲聊 / 无关话题 / 纯娱乐性对话

## R：原文锚点

1. “治病必求于本。”（《黄帝内经·素问》·据公版原文核·阴阳应象大论篇第五）

2. “医之治病也，一病而治各不同，皆愈何也？岐伯对曰：地势使然也。”（《黄帝内经·素问》·据公版原文核·异法方宜论篇第十二）

3. “知标本者，万举万当；不知标本，是谓妄行。”（《黄帝内经·素问》·据公版原文核·标本病传论篇第六十五）

## I：核心解释

《黄帝内经》没有“一个方子治所有问题”的做法——它反复讲“治病必求于本”“一病而治各不同”“不知标本是谓妄行”。同一个问题，在不同的失衡方向、不同的时令、不同的环境、不同的个体身上，要走的路径完全不同。素问 + 灵枢因此不是一套单一方法，而是一组各自独立、能独立触发的分析视角。

本系统把这些视角拆成 **22 个子 skill**，入口只做一件事：**看用户的问题命中哪个子 skill 的触发场景，把它路由过去**。

### 使用原则

1. **自动路由**：说你的问题，系统自动匹配子 skill。
2. **先诊断后行动**：先匹配子 skill 诊断，再给行动方案。入口只负责“把问题归到哪个子 skill”，不产出行动方案。
3. **身心联动**：身心问题往往交织，可能跨 skill 组合使用，此时要指明先从哪个切入。

## A2：典型触发场景

1. 用户用日常话描述一个身心/生活问题，里面出现触发词或典型情境：累、虚、上火、失眠、换季不适、情绪带出身体症状、饮食偏嗜等。
2. 用户说不清“该用哪个角度”看自己的问题，需要系统帮他归到一个合适的分析视角。
3. 问题同时踩中多个视角（如既焦虑又上火又换季），需要判断先走哪条、要不要组合。

## E：执行步骤

路由流程（输入 → 输出）：

- **输入**：用户原话（用户对问题的描述）与该问题的情境信息（触发词、当下的身体或情绪信号、发生的时令与场合等，都取自用户自己的说法）。
- **输出**：命中的子 skill 名字 + 给用户看的一行路由说明——「我理解你的问题是「…」，匹配到 {子 skill 名}（{该子 skill 的触发场景}）。这个方向对吗？」。

1. **读问题、抓信号**
   **输入**：用户原话与情境 → **输出**：问题里的触发词/信号清单（身体或情绪信号、时令场合）。
   🔴 **CHECKPOINT**：信号不足时先追问一两个最困扰的信号，再继续匹配。

2. **匹配子 skill**
   **输入**：信号清单 → **输出**：命中的子 skill（或候选多个）。
   🔴 **CHECKPOINT：路由确认（匹配子 skill 后、给行动方案前必须确认）**。自动匹配到子 skill 后，先与用户确认路由方向再继续：

   ```
   🔴 我理解你的问题是「[你复述的问题]」，匹配到 {子 skill 名}（{该子 skill 的触发场景}）。这个方向对吗？
   - 对 → 按该子 skill 继续诊断
   - 不对，或还想覆盖其他方面 → 重新匹配，或说明需要哪几个子 skill 组合
   ```

   路由未确认前不输出行动方案。若问题涉及紧急生命安全，跳过路由，直接就医。

3. **交出路由说明**
   **输入**：命中的子 skill → **输出**：给用户的一行路由说明（先诊断后行动，不产出行动方案）。
   🔴 **CHECKPOINT**：路由说明发出后等待用户确认；确认后由选中的子 skill 在诊断之后给出行动方案。

## B：边界与失败模式

### 路由失败分支

路由不保证一次到位。下面几类情况出现时，按表处理，处理完仍要回到上面的 CHECKPOINT 再确认；任何分支期间都遵守“路由未确认前不输出行动方案”。

| 情况 | 表现 | 怎么办 |
|------|------|--------|
| 无匹配 | 问题落在系统范围内（身体、情绪、季节、饮食等），但 22 个子 skill 的触发场景都套不上 | 先追问一句，请用户补上最困扰的一两个信号；仍无匹配就说明本系统不覆盖，按反例清单直接回答 |
| 两个都像 | 同一个问题同时命中两个子 skill 的触发场景 | 把两个方向各自的理由说清，请用户选更贴近的那个；若确实交织，按「身心联动」组合使用，并指明先从哪个切入 |
| 用户否认路由 | 用户在 CHECKPOINT 回「不对，不是这个」 | 按用户的说法重新匹配；或请其说明还想覆盖哪几方面，改走子 skill 组合 |
| 命中后发现不适用 | 进入子 skill 后，它自己承认不适用于当前问题 | 停下这个子 skill，回到路由重新匹配或改走组合，不硬套 |
| 紧急生命安全 | 问题涉及急救、自伤等需立即行动的情形 | 跳过路由，直接建议就医/急救，不先做分析 |

### 边界规则

1. **路由未确认前不输出行动方案**；行动方案由选中的子 skill 在诊断之后给出。
2. **紧急优先**：涉及紧急生命安全，跳过路由，直接就医/急救。
3. **组合要指明切入顺序**：身心交织时按「身心联动」组合，并说清先从哪个子 skill 切入。

**安全兜底**：涉及就医、用药或心理危机时，只做提醒与陪伴，**不作医疗判断、不替代就医**。

## 练习手册

1. **做一次自查路由**：把自己最近的一个烦恼写成一句话，圈出里面的触发词/信号，对照子 skill 目录，说清为什么它更像某个子 skill。
2. **写一次路由确认话术**：按「我理解你的问题是「…」，匹配到 {子 skill}（{触发场景}）。这个方向对吗？」的格式，把它写一遍。
3. **练一次失败分支**：假设问题同时像两个子 skill，写下两个方向各自的理由，并给出“先从哪个切入”的建议。

> 本练习只用于练习路由判断，不作医疗判断、不替代就医。

## 灰色地带

- **问题像两个子 skill**：不是二选一，可能是“身心联动”的组合；先请用户选更贴近的，或改走组合并指明切入顺序。
- **范围内但套不上任何触发场景**：先追问一两个最困扰的信号；仍无匹配就承认本系统不覆盖，按反例清单直接回答。
- **进入子 skill 后才发现不适用**：不硬套，停下当前子 skill，回到路由重新匹配或改走组合。
- **紧急与分析的取舍**：涉及急救、自伤等需立即行动的情形，分析让位于行动，直接建议就医/急救。
