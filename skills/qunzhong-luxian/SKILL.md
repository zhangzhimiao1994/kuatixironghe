# 群众路线 — 四步无限循环用户洞察引擎

**来源**：《毛泽东选集》关于领导方法的若干问题(1943) ｜ 证据等级：firsthand

> *"在我党的一切实际工作中，凡属正确的领导，必须是从群众中来，到群众中去。"* — 毛泽东, 1943

## 触发条件

**应该触发**：
- 团队方案推不下去。
- 产品路线图脱离用户现实。
- 战略规划闭门造车。
- 用户反馈堆在工单系统无人提炼。
- 新产品上线后没人用。
- 已连续 2 周+ 没接触真实用户；或有一堆反馈但没提炼；或有方案但没回到用户中验证。

**不应触发**：
- 个人决策不需要团队参与（选午饭、选主题）→ 群众路线过重。
- 紧急危机（现金流断裂等）→ 来不及走循环，直接决策。
- 颠覆性创新（0→1）→ 用户无法预见自己需要什么。
- 用户自身认知不足以提供有效反馈的领域（前沿 AI／B2B 深水区）→ 需专家判断。

### 速查：启动决策树

```
用户反馈/需求/方案推不下去
    │
    ├─ 是紧急危机（现金流断裂等）？ ────→ ❌ 别用，直接决策
    ├─ 是颠覆性创新探索？ ──────────→ ❌ 别用，用户不知道要什么
    ├─ 用户自己认知不足（前沿AI/B2B深水区）？ → ❌ 别用
    ├─ 已连续2周+没接触真实用户？ ────→ ✅ 激活：从步骤1开始
    ├─ 有反馈但未提炼（工单堆着）？ ──→ ✅ 激活：从步骤2开始
    └─ 有方案但没验证？ ────────────→ ✅ 激活：从步骤3开始
```

## R：原文锚点

> "在我党的一切实际工作中，凡属正确的领导，必须是从群众中来，到群众中去。"（关于领导方法的若干问题，1943年）（已据原文核）

> "从群众中集中起来又到群众中坚持下去，以形成正确的领导意见，这是基本的领导方法。"（关于领导方法的若干问题，1943年）（已据原文核）

> "将群众的意见（分散的无系统的意见）集中起来（经过研究，化为集中的系统的意见），又到群众中去作宣传解释，化为群众的意见，使群众坚持下去，见之于行动，并在群众行动中考验这些意见是否正确。"（关于领导方法的若干问题，1943年）（已据原文核）

> "任何工作任务，如果没有一般的普遍的号召，就不能动员广大群众行动起来。"（关于领导方法的若干问题，1943年）（已据原文核）

## I：核心解释

1. **认知来自群众、回到群众**：正确的领导意见不是办公室里想出来的，是"从群众中来，到群众中去"——分散的、无系统的意见，经过研究化为集中的、系统的意见，再回到群众中去检验（R1、R3）。
2. **循环而非单次**：这不是一次调研就结束，而是"从群众中集中起来又到群众中坚持下去"的**无限循环**（R2）——每轮产出新洞察 → 新方案 → 新验证 → 新认知。
3. **加工是核心环节**：跳过"集中加工"直接照搬反馈是需求堆叠，不是洞察——这是群众路线与"用户说什么就做什么"的分水岭。
4. **反馈要回到用户中检验**："在群众行动中考验这些意见是否正确"——不回到实践，无法判断洞察对不对。
5. **必须防"尾巴主义"**：如果所有决策都被用户反馈直接牵着走，就丧失了"集中加工"的判断力。

## A1：来源应用

- **关于领导方法的若干问题（1943）**：毛泽东把党的一切实际工作中的领导方法概括为"从群众中来，到群众中去"，并指出分散意见必须经过研究"化为集中的系统的意见"，再回到群众中检验、坚持下去。
- **整风与根据地工作（1940年代，补充）**：把群众意见集中起来、化为政策，再拿到群众中宣传解释、见诸行动——这一"收集—加工—回到群众"的循环，是当时各项政策落地的基本方法。

## A2：典型触发场景

1. **产品路线图脱离用户**：NPS 很高、DAU 也在涨，但新功能上线后没人用，团队怀疑是"推广不够"。
2. **用户反馈堆积**：客服团队每周收到几百条反馈，产品经理却说"这些都是噪音，用户不懂产品"。
3. **一轮调研就停**：上个月做了用户调研，结论是"用户需要更快的加载速度"，优化后数据没变化。
4. **闭门造车**：战略规划全在会议室里完成，没有一线输入。

### 实测验证（test-prompts）

本 skill 在以下典型场景中经过了模拟验证：

**Test 1：产品路线图脱离用户**
> **用户**："我们的NPS很高，DAU也在涨，但新功能上线后没人用。是不是推广不够？"
> **预期**：skill 应诊断出"有收集无验证"——NPS和DAU是数据指标不是用户原话。激活步骤1收集原话，再进入完整循环。

**Test 2：用户反馈堆积**
> **用户**："我们客服团队每周收到几百条反馈，但产品经理说'这些都是噪音，用户不懂产品'。"
> **预期**：skill 应诊断出"有收集无加工"——反馈通道存在但缺集中加工环节。从步骤2开始，追问三层。

**Test 3：一轮调研就停止**
> **用户**："我们上个月做了用户调研，结论是用户需要更快的加载速度。优化之后数据没变化。"
> **预期**：skill 应诊断出"一轮就停"——一次调研的结论未经验证就执行。激活步骤3重新验证，并启动下一轮。

## E：执行步骤

### 四步无限循环（总览）

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  ① 分散收集 ──→ ② 集中加工 ──→ ③ 回到验证 ──→ ④ 再次循环  │
│       ↑                                            │    │
│       └────────────────────────────────────────────┘    │
│                                                         │
│  每轮产出：新洞察 → 新方案 → 新验证 → 新认知             │
└─────────────────────────────────────────────────────────┘
```

### 步骤1：分散收集（从群众中来）

**动作**：
- 每周安排 2 小时直接接触用户/一线（访谈、客服旁听、销售陪访）
- 收集时禁止过滤和判断——用户原话比数据报表更有信息量
- 建立"用户原话库"，每周新增 ≥10 条未经加工的原话

**如果步骤1失败**：
| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 用户不愿接受访谈 | 改用被动观察（客服录音、工单、App评论）替代主动访谈 | 标记"本周期数据源受限"，缩小结论置信度，下周期换渠道再试 |
| 收集到的反馈全是好评无实质性内容 | 改用问题导向提问："你用过的最不满意的功能是什么？"而非"你觉得怎么样？" | 若连续3周期仍全是好评 → 用户可能已沉默流失，激活流失用户回访专项 |
| 一线人员不配合提供反馈 | 先让一线人员自己体验收集来的反馈如何变成产品改进——让他们看到闭环的价值 | 仍不配合 → 缩小为一人深度访谈模式，不依赖批量数据 |
| 收集的原话 < 10条/周 | 降低门槛到 ≥5条，延长收集窗口到2周 | 连续2周期 <5条 → ⚠️ 可能是用户接触渠道本身断裂，先修复渠道再收集 |

🔴 **CHECKPOINT 1**：产出"本周用户原话库"（≥10条原始引用），用户确认已收集足够原始材料后进入步骤2。

### 步骤2：集中加工（化分散为系统）

**动作**：
- 每周做一次"碎片加工会"：把本周收集的用户原话分类、关联、提炼
- 追问三层：
  1. 用户说的是什么？（原话层面）
  2. 用户实际需要什么？（需求层面——跳过用户自己提出的解决方案，追问底层动机）
  3. 底层规律是什么？（系统层面——这不是一个人的问题，是一类人的问题）

**如果步骤2失败**：
| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 原话碎片化严重，看不出共性 | 增加分类维度（按用户类型/使用场景/情绪强度交叉切分），不要只按功能模块分类 | 仍无共性 → 先不做提炼，追加收集1周，扩大样本 |
| 团队对"底层规律"的判断不一致 | 每个人独立写出自己的提炼结论，然后对比差异点（而非共识点），差异点才是需要讨论的 | 仍不一致 → 保留分歧，标记"待验证"，在步骤3中让用户裁决 |
| 提炼出的洞察是"用户说A所以做A"（需求堆叠） | 强制追问："用户说A，但Ta真正想解决的问题是什么？这个问题有更好的解法吗？" | 仍无法跳出需求堆叠 → 标记本轮结论为"表面需求"，置信度设为"低" |

🔴 **CHECKPOINT 2**：产出"本周结构性洞察"1条（格式："用户说___，实际需要___，底层规律是___"）。用户确认洞察质量后进入步骤3。

### 步骤3：回到验证 + 启动下一轮

**动作**：
- 把步骤2的洞察转化为最小可验证方案（原型/话术/流程变更），回到用户中测试
- 记录验证结果：用户行为是否印证了洞察？
- 启动下一轮收集（回到步骤1）

**验证标准**（必须量化）：
- ✅ 验证通过：≥60% 测试用户的行为符合洞察预测
- ❌ 验证失败：<40% 符合 → 回到步骤1，追加收集，修正洞察
- ⚠️ 不确定：40%-60% 符合 → 拆分洞察为两个子假设，分别验证

**如果步骤3失败**：
| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 验证方案成本太高（需要开发） | 用低保真方案替代：纸质原型、对话脚本、人工模拟——不写代码也能验证 | 成本仍太高 → 缩小验证范围到3-5个核心用户，做深度访谈式验证 |
| 验证结果与洞察矛盾 | 不急着修正洞察——先检查验证方案是否正确传递了洞察的核心假设（方案可能歪曲了洞察） | 仍矛盾 → 退回步骤1，本轮洞察标记为"被证伪"（这本身是有价值的认知） |
| 验证完后团队不知该进入下一轮还是结束 | 检查：洞察是否还有未验证的部分？验证是否产生了新问题？只要有一项为"是" → 进入下一轮 | 两项都为"否" → 本轮闭环完成，归档结论，等待新信号触发下一轮 |

🔴 **CHECKPOINT 3**：产出"第N轮循环记录"（格式："我们之前以为___，实践证明___，新的认知是___，下一轮将验证___"）。

## B：边界与失败模式

### 失败模式分支表（if-then 三段式）

| # | 失败模式 | 触发条件 | 一线修复 | 仍失败兜底 |
|---|---------|---------|---------|-----------|
| 1 | **有收集无加工** | 用户原话库已建立但 ≥2 周未做碎片加工会 | 立即安排本周加工会，暂停新收集 | 加工会仍产出不了洞察 → 可能是团队缺乏提炼能力，引入外部 facilitator 帮助第一轮 |
| 2 | **有加工无验证** | 洞察已产出但 ≥2 周未做用户验证 | 立即用低保真方案验证，不追求完美方案 | 仍有阻力 → 检查阻力来源：是"不敢验证"还是"不知道验证什么"→ 前者需心理建设，后者需重新细化洞察 |
| 3 | **一轮就停** | 完成1轮循环后 ≥4 周未启动下一轮 | 强制用上次的新问题启动下一轮收集 | 团队认为"已经够了" → 检查是否真的够了：上次洞察的验证通过率是否 ≥80%？是则可以暂结，否则必须再跑一轮 |
| 4 | **群众尾巴主义** | 所有决策都直接被用户反馈驱动，丧失了"集中加工"的判断力 | 暂停收集1周，让团队独立做出一个判断，再回到用户中验证——用事实检验判断力 | 团队仍不敢独立判断 → 换一个决策者主导集中加工环节 |

### 边界规则

1. **循环要有终止条件**：洞察被验证通过（≥80% 符合率）且无新问题时可暂结——但"闭环"不等于"终止"，等待新信号触发新循环。
2. **至少两人参与加工**：一个人的"集中加工"本质上是主观主义。
3. **样本要有反面**：每次循环至少 20% 非活跃用户；每次验证至少 30% 中立或不满用户。
4. **常规方法，不是万能药**：面对范式转移（如 AI 冲击传统软件），用户反馈参考价值急剧下降。

### 用户自查清单

- [ ] 我本周接触了真实用户/一线（不是只看数据）
- [ ] 我做了集中加工，追问了"底层规律"
- [ ] 我的洞察回到了用户中验证
- [ ] 我保留了反面样本（非活跃/不满用户）
- [ ] 我已经在准备下一轮，而不是"一轮就停"

**勾选 4+ 项**：循环在健康运转。**≤2 项**：回到对应步骤重做，尤其别跳过步骤2。

**安全兜底**：若问题背后是持续的人际压迫、情绪耗竭或心理危机，只做提醒与陪伴，不做诊断，指向专业资源（心理援助热线 12356；紧急情况拨 120/110）。

### 🚫 红灯场景（绝对不要使用本 skill）

1. **现金流断裂等生存危机** — 没有时间做循环，直接决策。用「集中优势兵力」skill。
2. **颠覆性创新探索（0→1）** — 用户无法预见自己需要什么。亨利·福特："如果我问人们要什么，他们会说更快的马。"
3. **用户自身认知不足以提供有效反馈的领域** — B2B深水区技术产品、前沿AI研究等，需要专家判断而非用户反馈。
4. **个人决策不需要团队参与** — 选午饭、选编辑器主题等，群众路线过重。

### 作者盲点（使用本 skill 必须知道的限制）

1. **毛泽东假设"群众"利益统一** — 在商业场景中，不同用户群体利益常冲突（卖家 vs 买家、广告主 vs 用户）。面对对立诉求时，"集中加工"不能简单叠加，需引入trade-off判断。
2. **"一次比一次更正确"前提是组织有自我批判能力** — 如果团队文化是"证明老板是对的"，循环会变成自我强化的回音壁。使用本 skill 前确认组织是否有真诚反思的能力。
3. **群众路线是常规经营方法，不是万能药** — 面对范式转移（如AI对传统软件的冲击），用户反馈的参考价值急剧下降。

## 📖 练习手册

完整跑一轮循环：① 本周安排 2 小时接触真实用户，建立 ≥10 条原话库；② 开一次至少两人的碎片加工会，产出 1 条"用户说___，实际需要___，底层规律是___"的洞察；③ 把洞察做成最小可验证方案回到用户中测试，记录通过率并启动下一轮。记录"验证前 vs 验证后"的认知差异（补充）。

## 🚫 反例与黑名单

| # | 反模式 | 为什么不能做 | 正确做法 |
|---|--------|------------|---------|
| 1 | 用数据仪表盘代替用户原话 | 数据告诉你"发生了什么"，不告诉你"为什么"——DAU下降看不出是因为按钮太小还是用户不需要这个功能 | 数据 + 原话并行：数据定位问题域，原话解释原因 |
| 2 | 收集完反馈后直接提需求给开发 | 跳过了"集中加工"环节，这是需求堆叠不是洞察——用户的解决方案通常不是最优解 | 必须先追问三层再转化为需求 |
| 3 | 只调研付费用户/活跃用户 | 幸存者偏差——流失用户、沉默用户的声音才是增长瓶颈的关键 | 每次循环至少包含20%非活跃用户 |
| 4 | 验证只找"友好用户" | 友好用户会给你面子不会说真话——验证结论是自我安慰 | 每次验证至少包含30%中立或不满用户 |
| 5 | 把无限循环理解为"永远不停" | 每轮循环必须有终止条件——洞察被验证通过（≥80%符合率）且无新问题产生时可以闭环 | 闭环不等于终止：归档结论，等待新信号触发新循环 |
| 6 | 用问卷代替访谈/观察 | 问卷是用户"认为"自己会做什么，访谈/观察是用户"实际"做什么——两回事 | 至少50%数据来自行为观察或深度访谈 |
| 7 | 集中加工变成一个人的工作 | 个人偏见和盲点无法被修正——一个人的"集中加工"本质上是主观主义 | 至少2人参与加工会 |

### 灰色地带（需谨慎判断）

- **用户诉求彼此对立（卖家 vs 买家、广告主 vs 用户）** → 不简单叠加；先找主要矛盾（转 maodun-fenxi），再做 trade-off。
- **组织缺乏真诚反思、只想"证明老板对"** → 循环会退化为回音壁；先修复组织的反思能力再跑循环。
- **颠覆性创新/范式转移阶段** → 用户反馈参考价值下降，本 skill 权重调低，改以专家判断与实验为主。
