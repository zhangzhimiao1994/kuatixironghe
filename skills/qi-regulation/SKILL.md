# 调气治本框架

## 触发条件

- 一直在"灭火"但问题反复出现，需要从"治形"转向"调气"。
- 某个系统（团队/身体/流程）的核心功能不正常，直接干预无效，需要恢复其运行状态。
- 问题存在很长时间，多种方法都试过但无效，需要"治本"思维。
- 不触发：纯信息查询、没有系统失调的场景、只需描述现象不需解决的场景。

## R：原文锚点

> 用针之类, 在于调气。气积于胃, 以通营卫, 各行其道。
> 凡用针者, 虚则实之, 满则泄之, 宛陈则除之, 邪胜则虚之。
> 气至而有效, 效之信, 若风之吹云, 明乎若见苍天。
>
> — 灵枢·据公版原文核·刺节真邪、灵枢·据公版原文核·九针十二原

## I：核心解释

调气治本框架是一个从"处理表面症状"转向"恢复系统功能状态"的元方法论。

其核心操作分为四层:

1. **识形气**: 区分"形"(表面表现/结果)和"气"(功能状态/原因)。症状是形, 导致症状的功能失调是气。头痛是形, 气血不通是气; 团队效率低是形, 沟通通道阻塞是气。

2. **调气而非治形**: 干预的目标不是消除表面现象, 而是恢复系统的正常运行功能。"用针之类在于调气"——一切手段都服务于恢复功能状态这个根本目标。


3. **四个方向**: 虚则补(增益不足), 实则泻(祛除多余), 宛陈则除(疏通淤滞), 邪盛则祛(排除干扰)。先判断属于哪种情况, 再选方向。
   🛑 **STOP**：请确认上一步的分析结果后再继续。


4. **有效的验证标准**: "气至而有效"——系统产生积极反应是干预有效的标志。效果应该是可感知、可验证的, "若风之吹云"般清晰。

这个框架的威力在于: 将注意力从"问题表现"转移到"系统功能", 从"消灭症状"转移到"恢复秩序"。

## A1：来源应用

### 案例 1: 久病不愈的根因
- **问题**: 久病是否不可治?
- **方法论的使用**: 岐伯用四个比喻回答——"刺虽久犹可拔也, 污虽久犹可雪也, 结虽久犹可解也, 闭虽久犹可决也"。关键不是病了多久, 而是方法对不对。"疾虽久犹可毕也, 言不可治者未得其术也。"
- **结论**: 问题拖得久不代表不能解决, 而是之前的干预一直在治形(处理表面), 没有调气(恢复功能)。
- **结果**: 找到正确的功能恢复路径, 久病也能治愈。

### 案例 2: 经脉不通的解结法
- **问题**: 一条经脉上实下虚, 气血不通, 如何处理?
- **方法论的使用**: "此必有横络盛加于大经, 令之不通"——先找到阻塞原因(横络压迫), 然后"视而泻之, 此所谓解结也"——在阻塞点精准疏通。
- **结论**: 不是整条经脉都有问题, 而是某个点阻塞导致全线不通。调气就是找到并疏通这个关键阻塞点。
- **结果**: 阻塞疏通后, 气血自然恢复流通, "营卫之行上下相贯如环之无端"。

## A2：典型触发场景

### 用户会在什么情境下需要这个 skill?

1. **反复处理表面问题无效**: 用户一直在"灭火"但问题反复出现, 需要从"治形"转向"调气"。
2. **系统功能失调**: 某个系统(团队/身体/流程)的核心功能不正常, 直接干预无效, 需要恢复其运行状态。
3. **长期问题久拖不决**: 问题存在很长时间, 多种方法都试过但无效, 需要"治本"思维。

### 语言信号 (用户的话里出现这些就应激活)

- "这个问题反复出现, 怎么也解决不了"
- "一直在救火, 从来没有从根本上解决"
- "各种方法都试过了还是不行"
- "感觉系统本身出了问题, 不只是某个环节"

### 与相邻 skill 的区分

- 与 `excess-deficiency-decision` 的区别: 调气治本是**元原则**(干预的目标是恢复功能), 虚实补泻是**操作方向**(具体该怎么补或泻)。先确定"要调气", 再用虚实补泻决定"怎么调"。
- 与 `bottleneck-unblock` 的区别: 调气治本是**思维方式**(关注功能而非形式), 解结通滞是**具体方法**(找阻塞点疏通)。调气是"为什么要这样做", 解结是"具体怎么做"。

## E：执行步骤

当 skill 被激活后, agent 应按以下步骤执行:

1. **区分形与气: 识别表面现象与功能失调**
   - 列出当前所有的"形"(可观察到的异常表现/症状), 然后追问每个"形"背后的"气"(是什么功能失调导致了这个表现)。
   - 完成标准: 每个"形"都找到了对应的"气", 且"气"是功能性描述而非现象重复。
   **输入**：当前所有可观察的异常表现（形）→ **输出**：每个“形”背后对应的功能失调（气）。

2. **判断属于四种情况中的哪一种**
   - 虚(功能不足→需要增益) / 实(功能亢盛→需要抑制) / 瘀(功能阻塞→需要疏通) / 邪(外部干扰→需要排除)。
   - 完成标准: 明确给出判断并说明依据。
   - 判停条件: 如果多种情况并存, 标记为"混合型", 分别处理。
   **输入**：识别出的功能失调 → **输出**：虚/实/瘀/邪（或“混合型”）的判断及依据。

3. **制定调气方案: 恢复系统功能**
   - 根据判断结果, 制定恢复功能状态的方案(补/泻/疏通/排除)。方案的目标是"系统恢复自主运行", 不是"持续依赖外部干预"。
   - 完成标准: 给出至少1个具体的功能恢复动作, 并说明恢复后系统应有的自主运行状态。
   **输入**：判断结果 → **输出**：恢复功能的调气方案（补/泻/疏通/排除）+ 恢复后应有的自主运行状态。

4. **验证有效性: "气至而有效"**
   - 设定干预后可观测的验证指标。效果应该是可感知、可验证的。
   - 完成标准: 明确列出"干预有效"的1-2个可观测标准。
   **输入**：已执行的干预 → **输出**：1-2个“气至而有效”的可观测验证标准。

🔴 **CHECKPOINT**：进入正式方案前，与用户确认"形→气"的对应关系与方向判断是否正确，未确认不进入执行。

## B：边界与失败模式

> 本 skill 只提供功能恢复的认知视角，**不作医疗判断、不替代就医、不自行尝试针刺**；文中调气/针刺表述仅为隐喻映射。

### 不要在以下情况使用此 skill

- **纯信息查询**: 用户只是想了解某个现象是什么, 不涉及系统功能失调, 不需要调气。
- **没有系统失调**: 如果系统运行正常只是外观不理想, 这不是功能问题, 调气框架不适用。

### 作者在书中警告的失败模式

- **治形不治气**: 只处理表面症状而不恢复功能, 等于扬汤止沸。"言不可治者未得其术也"——方法不对不是问题不能治。
- **方向错误**: 如果虚实判断错误(把虚当实去泻), 会加重功能失调。"虚而泻之则经脉空虚, 血气竭枯。"

### Fallback（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败 → 兜底 |
|---------|---------|-------------|
| 治气方向错误导致功能恶化 | 最快速纠正：反向操作。补了更差 = 方向反了 → 立即切换方向 | 两个方向都试了仍不行 → 不是单纯气机失调，考虑器质性/结构性原因 |
| 只治表面症状（治形）后反复 | 底层的功能问题没解决。退回步骤1：「这个症状的本质功能是什么？什么功能失调导致了它？」 | 追不到功能失调 → 可能不是功能失调，是功能设计本身有缺陷。考虑 `root-cause-priority` |
| 治气后症状消失了但新问题出现 | 「按下一个又冒出一个」→ 存在更深层根源。调用 `root-cause-priority` 追溯 | 根源找不到 → 接受：当前只能做症状管理。定期（每周）重新检查是否有新线索 |
| 把一切归咎于「气」而忽略结构 | 调气（功能）+ 调形（结构）要配合。先调气：如果功能恢复后问题不复发 → 不是结构问题 | 调气有效但维持不久 → 结构有深层缺陷需要改。不只是调气能解决的 |
| 治气后功能恢复了但用户不满意 | 功能恢复了 ≠ 体验好了。问：「功能正常了，但感觉上哪里还不舒服？」 | 感觉上的问题往往指向更细微的气机失调——治气治对了大方向但力度或精度不够 |
| 症状在治气过程中时好时坏 | 正常的气机调整波动。设观察期（3-7天），只要整体趋势向好就不干预 | 持续波动超过 2 周 → 可能有两股相反的气机在拉扯。需要先确定谁在拉谁 |

### 作者的盲点 / 时代局限

- 灵枢将一切失调归结为"气"的功能性概念, 但现代系统问题可能有结构性原因(如组织架构、技术债务), 此时"调气"(恢复功能)需要配合"调形"(改变结构)。

## 练习手册

**练习 1 — 分形气**
列出手上所有"形"（可观察的异常表现），逐一追问"是什么功能失调导致了它"，写出对应的"气"。

**练习 2 — 定方向**
对每个"气"判断属于虚 / 实 / 瘀 / 邪（并存则标"混合型"），并写出判断依据。

**练习 3 — 设验证**
为方案设 1-2 个"气至而有效"的可观测指标，写下"恢复后系统应能自主运行"的状态描述。

> 本练习只用于练习功能恢复思路，不作医疗判断、不替代就医、不自行尝试针刺。

## 反例黑名单

| # | 反例模式 | 为什么危险 | 正确姿势 |
|---|---------|-----------|---------|
| 1 | **治形不治气** | 只处理表面症状不恢复功能 → 扬汤止沸 | 每看到一个表面问题，问：「这个症状的本质功能是什么？什么功能失调导致了它？」 |
| 2 | **方向错误（虚当实泻）** | 虚实判断错 → 加重功能失调 | 确认方向前做反向校验：如果补了更差 → 方向反了，立即切换。两个方向都试了仍不行 → 考虑器质性原因 |
| 3 | **治气成功但新问题出现** | 按下一个问题又冒出一个 → 存在更深层根源 | 调用 root-cause-priority 追溯根源。表面的气机失调可能只是深层结构性问题的症状 |
| 4 | **把一切归咎于气而忽略结构** | 灵枢将一切失调归为气 → 现实有结构性原因（架构/制度/技术债务） | 调气（恢复功能）需配合调形（改变结构）。先调气再调形：如果功能恢复后问题不复发 → 不是结构问题 |
| 5 | **治气后症状反复** | 功能临时恢复了但底层没变 → 反复发作 | 症状反复 = 功能失调的根本原因没解决。从步骤 1 重新开始，这次追问更深一层：「为什么这个功能会失调？」 |

## 灰色地带

- **形 vs 气**：边界在"追到功能性描述"——若"气"只是把症状换个说法，说明还没追到底。
- **调气 vs 调形**：功能恢复后不复发 → 非结构问题；恢复后维持不久 → 结构有缺陷，需配合调形。
- **方向不明**：宁可先做低风险的一侧；补了更差立即反向，两方向都无效则考虑器质/结构原因。
- **症状波动**：治气过程中时好时坏属正常波动，设 3-7 天观察期，超 2 周持续波动则可能有两股相反气机在拉扯。
