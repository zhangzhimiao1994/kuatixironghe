# 跨体系多维分析器 (Cross-System Hub) v3.0

**模式**: Meta-Hub | **触发**: ≥2 个维度命中 | **深度**: L1-L4 自适应 | **维度**: 见 `dimensions.registry.md`（唯一注册处；本文件里的"体系"与"维度"同义）

---

## 输入 Schema

```yaml
required:
  user_complaint:        # string, 用户核心诉求, min_len=10, max_len=2000
  emotional_state:       # string, 情绪状态描述, enum=[焦虑/抑郁/愤怒/空虚/迷茫/疲惫/平静/其他]
  situational_context:   # string, 处境背景, min_len=20

optional:
  personal_history:      # string, 个人成长史/重大经历, max_len=1000
  recent_events:         # string, 近期发生的事件, max_len=800
  physical_symptoms:     # string, 身体症状, 按注册表给"身体"类维度权重+2
  relationship_status:   # string, 关系状态, 按注册表给"关系"类维度权重+1
  dreams:                # string, 梦境内容, 按注册表给"心理"类维度权重+2
  recurring_patterns:    # string, 反复出现的模式, 按注册表给"心理"类维度权重+2
  explicit_request:      # string, 用户明确要求, enum=[全面分析/主要矛盾/身体优先/心理优先/策略优先]
```

## 输出 Schema

```yaml
primary:
  activation_matrix:     # dict, 全部已注册维度的激活矩阵 {维度名: {weight: int(0-5), evidence: string}}
  priority_ranking:      # list, 优先级排序 [{system: string, level: int, reason: string}]
  system_analysis:       # dict, 逐维度分析 {维度名: {perspective, insight, action}}
  crosswalk:             # list, 互译项 [{concept, translations: {维度名: string}, resonance: bool}]
  tension_points:        # list, 维度间张力 [{systems, conflict, resolution}]
  synthesis:             # string, 综合洞察, min_len=100, max_len=1500
  resonance_core:        # string, ≥3 个维度共振的核心发现

secondary:
  depth_level:           # string, enum=[L1轻量/L2标准/L3深度/L4全景]
  integrated_actions:    # list, 整合行动 [{priority, action, source, mvf: bool}]
  fallback_plan:         # string, 如果首要行动失败的备选
  followup_template:     # string, 21天追踪模板（仅L4输出）
```

## 触发条件

**✅ 必须触发**（命中任一）：
- 用户表达复杂困境，语义扫描命中 ≥2 个维度的触发信号（信号表见 `dimensions.registry.md`）
- 用户明确说"全面分析""从多个角度看""综合诊断""多维度看看"
- 用户的问题在一个维度里不够（如既有心理症状又有身体症状）
- 之前的单一维度分析有盲区，用户追问"还有别的角度吗"

**❌ 禁止触发**（命中任一）：
- 问题明确属于单一维度范畴 → 直接路由到对应 skill
- 需要精神科紧急干预（自杀/自伤意念）→ 停止分析，提供危机资源
- 用户只需要简单信息查询（如"黄帝内经是谁写的"）
- 用户说"简单说说""一句话"→ 降级为单一维度快速回复

**流程分支规则**：
- STEP 1 → 若激活体系 < 2：返回 `"问题更适合用单一体系分析，建议尝试 [最相关skill]"`
- STEP 2 → 若检测到自杀/自伤意念：立即执行 C5，不进入后续STEP
- STEP 3 → 若某体系权重 ≤ 2：仅输出1句视角，不展开三要素
- STEP 5 → 若检测到 ≥ 2 组严重冲突：执行 C3 阶段化方案
- 任意STEP → 若用户说 "太多/听不进去"：执行 C4 降级到 L1

### STEP 1：体系激活扫描 🔍

**数据流**:
```
输入: {user_complaint, emotional_state, situational_context, optional_fields}
  ↓
处理: 逐体系语义匹配 → 权重计算 → 激活判定
  ↓
输出: activation_matrix = {体系名: {weight: int(0-5), evidence: string}}
```

**输入**: user_complaint + emotional_state + situational_context + optional fields
**输出**: activation_matrix (全部已注册维度 × 权重0-5)
**前置条件**: 用户输入 ≥ 50 字，或已追问补充
**不满足时**: 执行 C1（输入信息不足）

**权重计算伪代码**：
```
def calculate_weight(system, text, optional_fields):
    keyword_hits = count_keywords(text, system.keyword_table)
    semantic_strength = semantic_match(text, system.core_concepts)  # 1-3
    optional_bonus = 0
    
    optional_bonus = registry_bonus(system, optional_fields)
    # ★ 加成规则写在 dimensions.registry.md（如身体症状 → "身体"类维度 +2；梦/反复模式 → "心理"类维度 +2）
    #   症状不论填在 physical_symptoms 字段、还是写在用户诉求正文里，只要语义命中该维度的触发信号，就按同样加成处理
    #   本文件不写死维度名，加维度不改这段代码
    
    weight = keyword_hits + semantic_strength + optional_bonus
    return min(weight, 5)  # 上限5
```

**扫描规则**：
```
对每个体系：
  0. ★ 先过「硬闸门」：注册表 dimensions.registry.md 里列为硬闸门的维度，
     只有在用户**显式**用了它的显式词时才继续；未显式请求 → 直接 weight=0、evidence 留空，
     **并且这一轮不显示该维度**（激活矩阵与正文里整行都不出现，连「本轮不激活」都不写）；
     不许用泛化词（山、水、朝向、地势、环境、方位、宅子…）填 evidence，也不许推测。
  1. 提取命中文本（原文字符串切片）
  2. 语义匹配触发信号关键词表
  3. 计算权重 = 关键词命中数 + 语义强度(1-3) + optional字段加成
  4. 输出 evidence = 具体命中文本依据
```

**权重判定标准**：
- 5 = 高置信命中（多个强信号+optional字段加成）
- 4 = 明确命中（核心信号明确）
- 3 = 标准命中（有相关信号）
- 1-2 = 弱信号（边缘关联，仅交叉引用）
- 0 = 无信号（本轮不激活）

**激活阈值**：
- ≥4：必须深度展开（完整分析 + 互译 + 行动）
- 3：标准展开（分析 + 轻量互译）
- 1-2：轻量提及（1-2句交叉引用）
- 0：不展开

🔴 **CHECKPOINT 🛑**: 确认每个体系命中都有具体文本依据。
如果 evidence 为空或模糊 → 追问用户补充信息，**禁止凭空激活**。

**不满足时**: 返回 STEP 1 追问

### STEP 2：体系优先级排序

**数据流**:
```
输入: {activation_matrix, explicit_request}
  ↓
处理: 危机层级排序 → explicit_request调整 → 严重身体症状置顶
  ↓
输出: priority_ranking = [{system: string, level: int, reason: string}]
```

**输入**: activation_matrix + explicit_request
**输出**: priority_ranking (排序后的体系介入顺序)
**前置条件**: activation_matrix 已完成且 ≥2个体系激活
**不满足时**: 返回 STEP 1 重新扫描

**默认排序（危机层级）**：
```
L0 🆘 生命安全层：任何体系发现自杀/自伤意图 → 立即停止，危机干预
L1 🏥 身体基础层（身体类维度）：身体是承载一切的基础
L2 🧠 心理与关系层（心理、关系、依恋、EFT 类维度）：严重压抑/创伤/关系冲突 → 先被看见才有分析空间
L3 🌱 成长与行动层（成长、习惯、专注类维度）：安全/基础稳定后才谈成长
L4 🗺️ 策略行动层（决策、组织类维度）：前几层稳定后才能有效执行
L5 ⏳ 时位与象征层（象征、校准类维度）：需要清醒头脑，放最后补充

**同层内的先后**按 `dimensions.registry.md` 的"顺序"列；新维度按其"层"入座，不改本表。
```

**特殊调整规则**：
- explicit_request=身体优先 → 身体类维度提前到L1
- explicit_request=主要矛盾 → 决策框架提前到L2（帮助厘清混乱）
- explicit_request=策略优先 → 决策框架提前到L3
- physical_symptoms 严重（胸痛/咳血/持续剧痛）→ 黄帝内经提到最前，建议立即就医

🔴 **CHECKPOINT ✅**: 确认身体层和压抑层不晚于策略层。
如果排序违反此规则 → 重新调整。

**不满足时**: 重新排序，确保 L1(身体) 和 L2(心理) 在 L4(策略) 之前

---

### STEP 3：逐体系分析

**数据流**:
```
输入: {priority_ranking, 用户完整输入}
  ↓
处理: 按优先级逐个分析 → 权重决定深度 → 输出三要素
  ↓
输出: system_analysis = {体系名: {perspective, insight, action}}
```

**输入**: priority_ranking + 用户完整输入
**输出**: system_analysis (每个激活体系的三要素)
**前置条件**: priority_ranking 已完成
**不满足时**: 回到 STEP 3 重新调整输出粒度

**输出格式模板**（严格按此格式）：
```
【体系名】权重=X/5
  视角: [1-2句话，该体系如何看这个困境]
  洞察: [1-2句话，用户可能没意识到的深层发现]
  行动: [1个最小可行行动，现在就能做]
```

🔴 **CHECKPOINT 📋**: 确认分析深度符合权重规则：
- 权重≥4 的体系：完整三要素，每要素≥30字 ✅
- 权重=3 的体系：精简三要素，每要素≥15字 ✅
- 权重≤2 的体系：只输出"视角"一句话 ✅

**不满足时**: 回到 STEP 3 重新调整输出粒度

### STEP 5：洞见冲突检测 ⚠️

**数据流**:
```
输入: {system_analysis}
  ↓
处理: 对比各体系行动建议 → 检测方向相反 → 标记张力 → 阶段化方案
  ↓
输出: tension_points = [{systems, conflict, resolution}]
```

**输入**: system_analysis
**输出**: tension_points (0-3条体系间张力)
**前置条件**: STEP 3 已完成所有体系分析
**不满足时**: 回到STEP 3重新检查
**后置动作**: 输出 tension_points（0-3条），每条含 systems/conflict/resolution

**常见冲突模式**（预定义）：

| 冲突对 | A体系建议 | B体系建议 | 张力本质 |
|--------|----------|----------|---------|
| 弗洛伊德 vs 内经 | 深挖创伤根源 | 先调气血不问原因 | 因果vs功能 |
| 毛选 vs 周易 | 主动出击解决 | 暂时退守等待时机 | 行动vs时机 |
| 荣格 vs 弗洛伊德 | 面向未来整合 | 回溯童年修复 | 方向性差异 |
| 内经 vs 荣格 | 身体优先调理 | 个体化探索 | 载体vs目标 |
| 毛选 vs 荣格 | 明确主要矛盾 | 接纳矛盾共存 | 解决vs整合 |

**处理方式**：
1. 检测：对比各体系"行动"建议，方向相反即标记张力
2. 标注：输出"体系间张力"——不强行调和
3. 阶段化：给出"当前阶段优先A，如果出现X信号则切换B"
4. 尊重：承认不同体系的适用范围差异

🔴 **CHECKPOINT 🛑**: 绝不强行"调和"——张力本身就是有价值的诊断信息。
如果检测到冲突但没有标注 → 回到STEP 3重新检查。

### STEP 6：合成洞察

**数据流**:
```
输入: {system_analysis, crosswalk, tension_points}
  ↓
处理: 提炼共振点 → 提炼互补点 → 构建综合判断 → 输出关键句式
  ↓
输出: {synthesis: string, resonance_core: string}
```

**输入**: system_analysis + crosswalk + tension_points
**输出**: synthesis + resonance_core
**前置条件**: crosswalk 和 tension_points 均已完成
**不满足时**: 回到 STEP 4 补充互译，或回到 STEP 3 重新检查各体系洞察的交集

🔴 **CHECKPOINT 🔥**: 确认已标注所有 ≥3 体系共振点。
- 检查 crosswalk 中是否有 🔥 标记
- 确认 synthesis 中 resonance_core 非空

**不满足时**: 回到 STEP 4 补充互译，或回到 STEP 3 重新检查各体系洞察的交集

**合成规则**：
1. **不重复**各体系结论
2. 提炼**共振点**：≥3个体系指向同一发现 → 核心问题，可信度最高
3. 提炼**互补点**：A解释不了的，B补上了
4. 输出格式：
   - 第一句：跨体系综合判断（一句话）
   - 第二段：共振点详细说明
   - 第三段：互补点/张力说明
   - 第四段：关键判断（"这不是…而是…"句式）

### STEP 7：整合行动建议

**数据流**:
```
输入: {synthesis, priority_ranking}
  ↓
处理: 按优先级排序行动 → 验证MVF → 标注来源 → 检查数量
  ↓
输出: integrated_actions = [{priority, action, source, mvf: bool}]
```

**输入**: synthesis + priority_ranking
**输出**: integrated_actions (按优先级排序的行动列表)
**前置条件**: synthesis 已完成
**不满足时**: 回到 STEP 7 重新设计第一个行动，或执行 C4 降级到 L1

**输出格式模板**（严格按此格式）：
```
🥇 优先1 [体系名]: 具体行动（≤20字）
   为什么现在做: 一句话
   怎么做: 2-3个具体步骤
   预期信号: 做了之后会有什么变化

🥈 优先2 [体系名]: 具体行动（≤20字）
   ...

🥉 优先3 [体系名]: 具体行动（≤20字）
   ...
```

🔴 **CHECKPOINT 🥇**: 确认第一个行动是最小可行行动（MVF）：
- [ ] 可以在 5 分钟内开始
- [ ] 不需要复杂准备
- [ ] 有明确的"完成"标准

**不满足时**: 回到 STEP 7 重新设计第一个行动，或执行 C4 降级到 L1
- 每个行动标注来源体系
- 行动数 = 激活体系数 - 1（最多5个，最少2个）
- 如果用户显式请求 L1 → 只输出优先1

## 输出纪律（逐步展示：STEP 1–7 全部写进正文）

> 自 **v3.11.0** 起，**正文就是 A 节 STEP 1–7 的逐步呈现**：从激活扫描到整合行动，每一步都要写出来，让用户看见结论是怎么来的。**不再有"内部推演 / 用户版"两套东西**——内部分析的产物就是正文。本节七条与 F 节反例、G 节自检同属质量闸，任一条不满足即视为不合格输出。

1. **逐步展示（第一硬条）**：正文按 STEP 1 → 7 分节写全，**一节能短、一节不能省**（例外只有第 8 条两种情形）：
   - **STEP 1 激活扫描**：给**激活矩阵表**——`维度 | 权重(0–5) | 命中的用户原话`。**权重 0 的维度也要列一行**并注「本轮不激活」，不得整表省略。**例外——注册表标了「硬闸门」的维度**：闸门没过就**整行不显示（不出现）**，连「本轮不激活」都不写（用户没点它，列出来是多嘴；这条与「权重 0 也要列一行」不冲突：那条管的是**过了闸门而没信号**的维度，这条管的是**闸门本身没过**的维度）。
   - **STEP 2 优先级**：给**排序表**——`维度 | 危机层级 L0–L5 | 排在这个位置的理由`。
   - **STEP 3 逐维度分析**：按 A 节原格式，**权重必须写出来**——`【维度名】权重=X/5` + 视角 / 洞察 / 行动三要素。权重 ≥4 每要素 ≥30 字；权重 =3 精简；权重 ≤2 只写一句视角。
   - **STEP 4 互译**：给**互译表**，3–8 条（只选与本次困境相关的），每条后一句「这意味着什么」；≥3 个维度同指一个概念 → 打 🔥共振。
   - **STEP 5 张力**：0–3 条，每条含 `维度对 / 冲突 / 阶段化处理`，标 ⚠️，**不强行调和**。
   - **STEP 6 合成**：按 A 节四段——一句话跨维度判断 / 共振点 / 互补与张力 / 「这不是…而是…」关键判断。
   - **STEP 7 整合行动**：按 🥇🥈🥉 格式，标来源维度 + 为什么现在做 + 怎么做 + 预期信号；行动数 = 激活维度数 − 1（2–5 个）。
   - **平台不支持表格时**（如飞书正文渲染不了 markdown 表格）：激活矩阵表、优先级表、互译表改用**平台原生的表格/卡片消息**发（Hermes：`send_feishu_table` / `send_feishu_card`）；**不得**把 markdown 表格塞进正文充数，也不得因平台限制就省略表格。
2. **结论速览放最前**：正文开头先给一段 3–5 行的**结论速览**（STEP 6 那句跨维度判断 + 最优先的一件事），让只读第一屏的人也拿到判断；速览之后 STEP 1–7 逐步写全。**速览不得代替逐步推演**。
3. **每一步都要有用户的原话做依据**：激活矩阵的「命中」列必须是他自己说过的话（原话切片）；**证据为空或模糊的不得激活**（同 STEP 1 CHECKPOINT）；拿不准的写「信号弱，供参考」，不硬凑。
   - **权重 ≥4 的维度，「依据要看得见」**：能引原书原句就引（带出处，如「（《周易》第三卦）」「（第3章 JUDGING JUDGMENTS）」）；**没有原典可引的**（框架类，如依恋／荣格／决策框架），就**说明判据来自哪条框架、或这个人的哪句原话**——两条路都算数，**不许空着不提**。
   - **引了原文就必须与这句判断对得上**：贴一句不相干的原文凑锚点，按「依据偏薄／答非所问」处理，**不给分**。
   - **为什么这么定**（v3.19.5 改）：原写法是「**必须**带原文锚点」，实测会把作答方推向**为引而引**——最省力的做法是抓一句长得像的原文贴上，量出来的是「引书合规」而不是「分析更准」。而 3 位独立评委对旧族 28 份的原话是「推演清楚／动作可打勾／边界守住，**但**无出处」——**分析力本来就在，缺的只是引用**。判据改成「依据看得见」，既保住准确，也不逼出形式主义（好用优先）。
4. **必须落到行动**：结尾给出「今天/这周能做的一件事」，具体到能打勾验证——与 F#7、STEP 7 的最小可行行动一致，没有可验证行动的回答不算完成。
5. **不把球踢回用户**：**先给判断，再请用户校正**；最多问 2 个问题，且先给初步结论。追问是补充（见 C1/C6/C7），不是正文主体；也不能替用户拍板（见「边界与限制」6）。
6. **贴合处境（反模板）**：判断必须落在**这个人的具体事实**上——用他给的场景、时间、人物、原话。**版式是规范、必须一致**（v3.11.0 口径）；不许复用的是**内容**：换个人就套不进去，激活矩阵的命中词、逐维度的洞察与行动都得是他自己的事。
   - **自造简称仍不给用户**：「两栏」「三问」「收工五步」「投一票」「旧设定」这类方法零件的自造叫法，正文里不出现。
   - **但体系术语与编号必须写出来**：**维度名、权重、危机层级、STEP 编号**属于规范正文，**省略即不合格**（与 v3.10.x 的旧口径相反）。
7. **输出先规划；能一条就一条，确属太大才拆，宜少不宜多——绝不截断**：
   - **动笔前按 STEP 规划**：哪几节合成一条、哪几节另起一条，先定好再写。**默认一条发完**；被客户端折叠（「展开/收起」）**不是**拆分理由。
   - **分条边界只能落在 STEP 之间**：**一个 STEP 不得横跨两条消息**；一个维度的三要素不得被切在两条里。
   - **绝不截断、绝不删内容**：不截断句子/表格/清单，也不得为了塞进一条而删内容；拆完的整体必须与未拆时等价。每条自带「第 n/m 条」与该条覆盖的 STEP 标题。
8. **两种例外**：① **🆘 危机场景不适用逐步展示**——按 C5 立即停止分析，只给安全资源与陪伴；② 用户明说「太多/听不进去」→ 按 C4 降级到 L1，此时保留 STEP 1（简表）+ STEP 7 最优先一条，**仍不得退化成没有过程的结论**。

**长度**：逐步展示优先，**不设 800 字上限**（v3.11.0 废止旧口径）；但仍不写废话、不堆术语、不复述用户已知的信息。

**记忆开关状态不进正文**（v3.11.3）：是否加载了历史、按 `fresh` 还是 `resume` 跑，属于执行者的内部状态，正文里一个字都不写——不写「无历史可加载 / 本次按 fresh 跑」这类交代，正文只写本次分析本身。

## 排盘数据与星历（象征层前置）

象征层（托勒密星盘）**要报具体盘面配置，前提是手里有一张真盘**。完整规范见 `docs/排盘与星历.md`；要点：

1. **有出生信息 + 有 Python** → 按**国内镜像**装纯 Python 星历库，再用包内脚本排盘：
   ```
   python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple pymeeus
   python tools/paipan.py --date 1994-11-10 --time 07:30 --tz 8 --lat 28.4546 --lon 117.9686
   ```
   （清华镜像不通时换 `-i https://mirrors.aliyun.com/pypi/simple/`）**本包一律走国内源**，整包依赖一次装完：`python tools/install_deps.py --install`。拿到上升/中天与七政黄经后，**才可以**引用具体配置。
2. **排不出盘**（没 Python / 没网 / 装不上）→ 只走**读法层面的倾向**：一句白话把倾向指回书上那一类 + **≥2 条**他能拿自己经历去对的对照 + 一个能打勾的动作；**不得报任何具体盘面配置**。
3. **只有时段没有准点**（如「辰时」7–9 点）→ 可以排，但**必须标注不确定度**：上升/中天在该时段内会大幅移动（实算例：上饶 1994-11-10，07:00 上升天蝎 23°40′ → 09:00 射手 19°32′，跨了一个星座），据此的判断一律标「未校正」；行星所在星座通常可用。
4. **降级只用一句用户听得懂的话交代**（「手里没有可算的盘」），不写内部话。

## B：联动深度等级 (L1-L4)

| 等级 | 激活体系 | 输出内容 | 适用场景 |
|------|:-------:|---------|---------|
| **L1 轻量** | 2–3 个 | 各1行洞察 + 1个最小行动 | 时间有限/问题简单 |
| **L2 标准** | 4–6 个 | 完整分析 + 互译表(3-5条) | 默认模式 |
| **L3 深度** | 全部激活（≥7） | + 张力检测 + 共振点识别 | 人生重大困境 |
| **L4 全景** | 全部激活 | + 21天追踪计划 + 个性化仪式 | 系统性转变 |

> **v3.11.0 起**：L1–L4 **都按「输出纪律」逐步展示**（激活矩阵 → 优先级 → 逐维度 → 互译 → 张力 → 合成 → 行动）。深度只决定**激活几个维度、每条写多细**，不决定「给不给用户看过程」。

**深度自适应规则**：
- 用户首次使用 → 默认 L2
- 用户说"深入说说""详细分析" → L3
- 用户说"帮我制定计划""系统改变" → L4
- 用户说"简单点""太长不看" → L1
- 检测到危机信号 → **立即停止全部分析**：不进入 STEP 3–7、不激活任何维度，按 C5 与 D 节 🆘 只给安全资源与陪伴（与 C5/D 节口径一致；旧版这里写“强制 L1 仍给 1 个行动”，与 C5/D 冲突，已废止）

## C：Fallback 机制

### C1: 输入信息不足

**触发**: 用户输入 < 50 字，或缺少 emotional_state/situational_context
**处理**:
```
1. 输出: "为了给你更准确的跨体系分析，我需要了解几个维度："
2. 追问模板（按优先级）：
   - "你现在最主要的困扰是什么？（一句话）"
   - "这件事让你感觉怎么样？（情绪）"
   - "最近身体状态怎么样？（睡眠/食欲/精力）"
   - "这件事发生在什么背景下？（工作/关系/家庭）"
3. 收到回答后 → 回到 STEP 1
```

### C2: 体系激活扫描歧义

**触发**: 某个体系权重在 2-3 之间（边界模糊）
**处理**:
```
1. 输出轻量分析（仅视角1句）
2. 标注: "[体系名]信号较弱，以下分析供参考"
3. 如果用户追问该体系 → 展开为标准分析
```

### C3: 体系冲突无法调和

**触发**: STEP 5 检测到≥2组严重冲突
**处理**:
```
1. 标注所有张力点
2. 输出: "不同体系给出了方向相反的建议。这很正常——说明你的处境本身存在内在张力。"
3. 给出阶段化方案:
   - "当前阶段（1-2周）优先：[体系A]方案"
   - "如果出现[信号X]，切换到：[体系B]方案"
   - "如果[信号Y]持续，建议寻求专业[领域]支持"
```

### C4: 用户认知超载

**触发**: 用户说"太多""听不进去"" overwhelm"
**处理**:
```
1. 立即停止输出
2. 降级到 L1: 只保留最优先1个体系 + 1个最小行动
3. 输出: "好，我们先做一件事：[具体行动]。其他的等你准备好了再说。"
4. 记录：下次触发时默认 L1
```

### C5: 紧急危机信号

**触发**: 任何体系扫描到自杀/自伤意念
**处理**:
```
1. 立即停止所有分析
2. 输出: "我听到你说你正在经历非常痛苦的时刻。我想先确认你的安全。"
3. 提供资源: 心理援助热线 12356 / 北京回龙观医院心理危机干预热线 010-82951332
4. 建议: "请尽快联系身边信任的人，或前往最近医院急诊科。"
5. 不继续任何分析
```

---

### C6: 用户质疑体系适用性

**触发**: 用户说"我不信中医""心理学都是骗人的""周易太玄了"等
**处理**:
```
1. 不辩护："没关系，你不一定要'相信'某个体系。"
2. 重新框架："这些体系本质是不同语言的'观察框架'，不是信仰。"
3. 提供替代："如果你对这个体系不感兴趣，我们可以重点看[其他高权重体系]。"
4. 询问："你最认同哪个视角？我们可以从那里开始。"
5. 调整激活矩阵：将该体系权重降为1（仅轻量提及），重新排序
```

### C7: 单体系分析严重跑偏

**触发**: 某个体系的洞察明显与用户的实际处境不符（如用户说"我最近升职了很开心"，但荣格分析说"你在逃避阴影"）
**处理**:
```
1. 自检："等等，这个分析和你的实际情况似乎对不上。"
2. 坦诚："可能是我理解错了，或者这个体系在这个点上不适用。"
3. 追问："你说的[具体事实]和[体系推断]之间，哪里感觉不对？"
4. 修正：根据用户反馈重新分析该体系，或将其权重降为边缘引用
5. 记录：将该误判记录到本次分析的"局限说明"中
```

**STEP 3 逐体系分析**（完整输出）:

【黄帝内经】权重=5/5
  视角: 你的身体在报警——"上实下虚"是核心病机。上面被职场的压力压着（实），下面是空的（虚），气血上不去也下不来，所以头晕头痛、没食欲、睡不好。
  洞察: 身体症状不是"体质差"，是你的身体在忠实地记录你被消耗的过程。失眠不是睡不着，是你的神（精神）不肯在危险的地方安歇。

  洞察: 你不是在恨自己，你是在用别人的标准惩罚自己。那个"干啥都不好"的声音，用的是谁的口音？
  行动: 写下一句你最常对自己说的自我否定的话，然后问自己："这是谁的声音？"

【毛选】权重=4/5
  视角: 你现在的处境是"多线作战"——身体、心理、工作、社交同时出问题。主要矛盾不是"我哪里不行"，而是"消耗速度远超修复速度"。

  行动: 画一张"消耗 vs 修复"收支表。左边列5个消耗你的人/事，右边列3个让你感到有力量的来源。

【荣格】权重=5/5
  视角: "自我否定"+"没有朋友"= 面具系统崩塌的信号。你之前戴的面具（职场角色、社交面具）已经撑不住了，但真实的自我还没长出来。
  洞察: 这不是你"变差了"，是你到了一个必须放下旧面具的关口。个体化的过程往往是先碎裂，再整合。
  行动: 找一个不需要表演的场景（可以是写日记、对信任的人、或者就是现在），说一句你从来不敢说的真话。

【周易】权重=3/5
  视角: 你现在在"剥"卦——山附于地，一层层被剥落。但剥极必复，复卦紧随其后。

**STEP 4 互译**（3条核心）:

|------|------|---------|------|------|:---:|

## F：反例黑名单（不要做什么）

| # | 反模式 | 为什么不要做 | 替代做法 |
|---|--------|------------|---------|
| 1 | **强行激活无关体系** | 为了"全面"而硬凑分析，降低可信度 | 权重=0 就诚实说"本轮不激活" |
| 2 | **强行调和体系冲突** | 抹杀不同体系的本体论差异 | 标注张力，给出阶段化方案 |
| 3 | **输出超长篇** | 用户认知超载，反而无效 | L1-L4 自适应，默认 L2 |
| 4 | **概念混用** | "气=力比多"是误译，不是互译 | 互译是桥梁，不是等价 |
| 5 | **跳过安全检查** | 自杀意念被当成"心理分析素材" | 任何危机信号 → 立即停止分析 |
| 6 | **用体系压人** | "周易说你该退"→ 替用户做决定 | 输出"时位分析"，让用户自己选 |
| 7 | **只给洞察不给行动** | 用户更困在"我懂了但动不了" | 每个体系必须有1个最小行动 |
| 8 | **忽视用户反馈** | 用户说"不对"还继续按流程 | 听到"不对"→ 追问哪里不对，调整 |
| 9 | **L4 默认输出** | 不是所有人都需要 21 天计划 | 按用户请求和困境复杂度自适应 |
| 10 | **把诊断当治疗** | 分析完就以为"解决了" | 明确区分"洞察"和"行动"，强调执行 |

## G：执行者自检清单

> 本 skill 建议搭配子 agent 实测验证。若无法运行子 agent，使用本清单自检输出质量。

### 每次执行后自检

**结构完整性检查**:
- [ ] 输出包含 activation_matrix（至少2个体系），**且正文里逐节写出来了**（激活矩阵表 → 优先级 → 逐维度三要素 → 互译 → 张力 → 合成 → 行动）
- [ ] 开头有 3–5 行的**结论速览**（跨维度判断 + 最优先一件事），且没有拿它代替逐步推演
- [ ] 输出包含 priority_ranking（按危机层级排序）
- [ ] 每个激活体系有 perspective + insight + action 三要素
- [ ] 互译表 ≥ 3 条（L2及以上）
- [ ] 第一个行动标注了"为什么现在做"

**安全边界检查**:
- [ ] 用户输入中无自杀/自伤意念（如有→已停止分析）
- [ ] 身体严重症状已建议就医（如有）
- [ ] 未强行激活权重=0的体系
- [ ] 未替用户做决定（"你应该…"→改为"[体系]视角建议…"）

**质量检查**:
- [ ] 共振点有 🔥 标记（≥3体系指向同一发现）
- [ ] 张力点有 ⚠️ 标注（未强行调和）
- [ ] 行动数 ≤ 5（按优先序取，不少于 1 个）
- [ ] 第一个行动可在5分钟内开始

**模板化检查（贴合处境，见「输出纪律」6）**:
- [ ] 第一段复述了用户的具体处境（他给的场景/时间/人物/原话），不是先摆方法
- [ ] 判断落在他/她的具体事实上，没有只给通用框架
- [ ] 正文**没有自造方法简称**（「两栏/三问/收工五步/投一票/旧设定」等）；**维度名 / 权重 / 层级 / STEP 编号已按规范写出来**
- [ ] 本回答不可与另一人的回答对调：换个名字套不进去
- [ ] 逐步展示**不受 800 字限制**（v3.11.0 废止旧上限），但正文没写废话、没堆术语、没复述用户已知信息

**分条发送检查（仅长输出需勾，见「输出纪律」7）**:
- [ ] 动笔前已**规划**条数与边界；**能一条发完就一条**（被折叠不算错）
- [ ] 只有确属太大才拆，且**条数宜少不宜多**（3–5 段内容不切五六条）
- [ ] **没有任何 STEP / 维度 / 一类信息被切在两条之间**，没有句子/表格/清单被截断
- [ ] 每条自带小节标题与「第 n/m 条」，单条可独立读懂；拆完与未拆等价

**L1-L4 深度检查**:
- [ ] L1: 逐步展示**照旧**（激活矩阵可简表），末尾只保留 1 个优先行动
- [ ] L2: 含完整分析 + 3-5条互译
- [ ] L3: + 张力检测 + 共振点识别
- [ ] L4: + 21天追踪计划

**dry_run 标注**: 若本次执行为模拟推演，在输出底部标注 `[dry_run: 建议搭配子 agent 实测验证]`

## J：通用性（不绑定任何 agent、模型或工具）

本包**不绑定**任何具体的 agent、模型、工具或版本：只要一个 agent 能读文本、能读写文件，就能用。

### 设计约束（改这个包时必须守住）

1. **不写死 runtime**：不出现某一家 agent 的名字、安装目录或版本号；路径一律写包内相对路径。
2. **不写死工具**：不说"用某个具体工具"，只说"读文件 / 写文件 / 检索"这类任何 agent 都有的动作。
3. **不写死模型**：不假定上下文长度、不假定联网、不假定多模态。
4. **只依赖两样东西**：本目录里的 markdown 文本 + 文件读写。脚本只用标准库（Python 3.8+ 即可，无需安装任何包）。
5. **一种身份**：包里的 skill 只有一种身份——**本包的 skill**。以后从别的书蒸馏出来的 skill 加进来，同样只是本包的 skill，不需要另立类别。

### 三种执行形态（按手上能力自适应，不要求任何一种）

| 形态 | 什么时候用 | 怎么跑 |
|---|---|---|
| **单 agent 顺序执行**（默认） | 任何有文件读写能力的 agent | 同一个 agent 顺序走完 STEP 1–7；用 G 节自检清单代替交叉验证 |
| **多 agent 并行**（可选加速） | 手上支持派生子 agent 时 | 按激活的维度拆分：每个子 agent 只做一个维度、只输出 perspective+insight+action；互译、张力检测、合成由主 agent 做 |
| **纯阅读参考** | 只读环境（人或无执行能力的 agent） | 只读 `SKILL.md` 与本注册表，按 A 节流程人工走 |

### 放置与加载

把 `skills/` 下的目录按**你所用的 agent 的 skill 放置约定**放进去即可（各 runtime 的约定不同，见其自身文档）。`input_schema` / `output_schema` 是说明性字段：读不懂的 runtime 直接忽略，不影响使用。

### 降级规则

- 派生失败或子 agent 超时 → 退回单 agent 顺序执行（在输出里补一句 `[已降级：单 agent 顺序执行]`）。
- 手边没有某本原书 → 只用该 skill 的 R / I / A / E 四节；引文仍需回书核对，没核对过就标注"未核对"。

## 边界与限制

1. **不替代医疗诊断**：任何体系分析都不能替代专业医疗/心理咨询
2. **不处理急性危机**：生命安全优先级永远最高
3. **不强制所有维度全开**：按激活判定，不强行激活
4. **不调和体系间根本冲突**：承认差异，不在哲学层面强行统一
5. **保持本体论独立**：互译是理解桥梁，不是概念等价
6. **不替用户做决定**：输出分析，选择权在用户
7. **不承诺治愈**：提供洞察和方向，不保证结果
