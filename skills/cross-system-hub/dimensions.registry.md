# 维度注册表（唯一注册处）

> 本文件是这套分析器**唯一**的维度登记处：hub（`SKILL.md`）的「维度概览与触发信号」、H 节名单、STEP 1 扫描与 STEP 2 排序都读这里。
> 加一个维度 = 本表加一行 + 建入口骨架 + 跑 `python tools/dim_check.py`（四处对齐才算完）。**hub 正文不再点名具体维度。**
> 校验：`python tools/dim_check.py`（注册表 ↔ skills/ 目录 ↔ hub 的 H 节 ↔ 计数）。

## 列

| 列 | 含义 |
|---|---|
| 顺序 | 同层内的书写先后；新维度取小数插空（如 5.5） |
| 维度 | 中文名，也是 hub 里显示的维度名 |
| 层 | `观察`（按用户陈述的事实分析）/ `象征`（要取数或出生信息）/ `校准`（只把判断改写成可检验命题） |
| 入口 | 该维度的 skill 目录规则（前缀或目录名） |
| 触发信号 | 白话说法；hub 的 STEP 1 语义扫描读这一列 |
| 数据依赖 | `—` / `心态或状态` / `一件具体的事` / `出生信息` |
| 来源 | 书或体系 |
| skill 数 | 该维度下的 skill 个数（`tools/dim_check.py` 会核对） |

## 硬闸门（显式请求才激活的维度）

有些维度**不能靠语义联想激活**——用户没明说要它，就不激活，权重写 0。判据是**显式词**，不是泛化词。

| 维度 | 硬闸门规则 |
|---|---|
| 16 堪舆择日 | **只在用户显式要「堪舆/看地」或显式要「择日」时才激活。** 触发它必须有显式词：相地一侧＝堪舆、风水、看地、相地、看宅、看形势、来龙、龙穴砂水、点穴、安葬、阴宅；择日一侧＝择日、挑日子、看日子、吉日、宜忌、神煞、黄道黑道、太岁、冲煞、建除、立成、用事。**泛化词一律不算**：山、水、河流、朝向、地势、地形、环境、方位、宅子、房子这些词单独出现时不激活、不推测。术语问句（「风水这个词到底指什么」「龙穴砂水是讲什么」）算显式，可以激活。 |
| 17 子平八字 | **只在用户显式要「八字/四柱」或显式要「看命」时才激活。** 显式词：八字、四柱、四柱八字、日主、命理、看命、排盘、排八字、用神、格局、十神、大运、流年、喜用神、调候。**泛化词一律不算**：生日、出生时间、属相、星座、几岁了、运气差、身体不好、感情不顺这些词单独出现时不激活、不推测（用户报生日可能是要排星盘、要记日程，不等于要看八字）。术语问句（「什么叫用神」「十神是讲什么」）算显式，可以激活。 |

**为什么**：这个维度最容易「顺手插一句」——用户谈工作压力时提到「最近搬到山边住」，那不是要你去看地。**硬闸门优先于触发信号的关键词匹配**（与成员 skill 自己的准入闸门同一口径、优先于它）。

**落地检查**：跑 STEP 1 时，标了硬闸门的维度先判闸门、后算权重；闸门不过就直接写权重 0 并把 evidence 留空，**不许用「山/水/朝向」这类泛化词填 evidence**。

**闸门不过＝不显示**：没过闸门的维度在**激活矩阵与正文里整行都不出现**，连「本轮不激活」都不写。（与「权重 0 的维度也要列一行」不冲突：那条管**过了闸门而没信号**的维度，这条管**闸门本身没过**的维度。）用户没点它，列出来就是多嘴。

**加这类维度时四处都要动**，清单见 `docs/扩展手册.md` 情形 B「新维度要不要设硬闸门」；`tools/dim_check.py` 会检查闸门落点是否齐全。

## 元工具（不是维度）

它们**不占维度行、不进 hub 的维度概览表、不参与 STEP 1 激活扫描与排序**；只在"维护这套包"的时候被用到。

| 元工具 | 作用 | 入口 | 来源 | 触发词（举例） |
|---|---|---|---|---|
| **zhengliu** | 把一本书 / 一个人蒸馏成可审计、可执行的 skill（即 `docs/扩展手册.md` 情形 C 的引擎） | `zhengliu/` | 自建 | 蒸馏、把这本书做成 skill、按这个人的方式做 |
| **darwin-skill** | 审计并优化已有 skill 的质量（含 runtime 中立性检查、评分与迭代） | `darwin-skill/` | 自建 | 优化 skill、给 skill 打分、skill 体检 |

**加一个元工具**：目录放进 `skills/` → 本表加一行 → `python tools/dim_check.py`。

## 同层内的排序规则（STEP 2 读）

- 危机层级（L0→L5）：生命安全 → 身体基础 → 心理与关系 → 成长与行动 → 策略与组织 → 时位与象征。
- 同一层内按本表「顺序」列排；新维度按其「层」入座，不改排序代码。
- `象征`与`校准`层永远排在观察层之后（需要清醒头脑；只调力度与节奏，不改方向）。

## 加一个维度

**一条命令（推荐）**：

```
python tools/new_dimension.py --prefix <前缀> --name <维度名> --layer <观察|象征|校准> \
    --signals "<触发信号，顿号分隔>" --source "<来源>" --skill <入口skill名> --emoji 🧩
```

它照 `templates/skill-template/` 建好 skill 骨架，在本表加行，在 hub 的概览表与 H 节补齐，自动同步描述行里的层计数，最后跑一次自检。

**手动版（三步）**：

1. 本表加一行（填「层 / 入口 / 触发信号 / 数据依赖 / 来源 / 顺序」）。
2. 照 `templates/skill-template/SKILL.md` 的九节建骨架：`skills/<slug>/SKILL.md` + `test-prompts.json`（≥3 条，覆盖应该触发 / 不应触发 / 边界）。
3. `python tools/dim_check.py`：注册表 ↔ `skills/` 目录 ↔ hub 概览表 ↔ H 节名单与计数，四处对齐。

**往已有维度再加 skill**：把新目录放进 `skills/`，在本表该维度的「skill 数」+1，在 hub 的 H 节该分组下补一行，再跑自检。
