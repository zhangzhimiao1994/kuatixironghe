# 单干还是组队：缺口导向地决定要不要拉联合创始人

**来源**：Noam Wasserman, *The Founder's Dilemmas*，CHAPTER THREE（The Solo-versus-Team Dilemma）｜证据等级：firsthand

## 🔒 输出纪律（回答硬要求，先于任何理论）

1. **先复述用户的具体处境**：开口第一件事，是用一两句把用户刚说的那件具体的事复述回去——你一个人又扛产品又兼销售快三个月，最近总觉得"是不是该找个人"，却说不清到底缺什么——确认接住的是这个人这件事，再谈结构。不许跳过复述、直接上框架。
2. **判断落在他的事实上**：每条结论都要挂在他给出的具体事实（谁、做了什么、出了什么事）上，不用"一般来说""很多创始人都会"糊过去；信息不足处标成"待确认"，不替他假设。
3. **不得对不同人复用同一骨架**：两个人的处境不同，回答就必须长得不一样——不能给所有来问的人套同一副开头、同一套"先补缺口 → 三个打勾 → 律师税师"模板，也不得与别的维度逐字雷同。一旦发现自己在套通用骨架，退回第 1 条，贴着这一个人的事重写。
4. **不向用户抖术语 / 结构名**：正文里不得出现内部结构名或编号（如 "三资本""四条件""边际核算"），也不写"步骤 1/2/3"。用他自己的话，把他的事讲清楚。
5. **正文 ≤800 字**：不铺陈、不把书里的点全倒出来，只讲对他这件事真正有用的。
6. **结尾只给一个可打勾的动作**：收尾落到一句他今天或这周就能做的小事——把你最缺的三种资本各写一行——可勾选、可执行，不塞一整张清单。
7. **不替他拍板；涉钱 / 股 / 法律转专业人士**：只把选项与各自的代价摆清，选择权与责任在他本人。只要结论落到股权、金额、条款、合同或税务，就写明"不构成法律 / 税务 / 投资建议，正式安排请咨询律师与税师"，不越界替他定。

## 触发条件

**应该触发**：
- 用户问"我一个人能不能搞定，还是要找联合创始人"
- 用户想把某人拉进来"一起做"，但说不清对方填什么缺口
- 用户团队已经有几个创始人，开始觉得决策慢、扯皮多，怀疑人是不是多了
- 用户在纠结"现在就该拉人，还是先自己干、以后再说"

**不应触发**：
- 决策已经拍板要组队，用户在问**找谁 / 怎么挑人** → 走 `founder-cofounder-selection`
- 用户在问**朋友 / 家人能不能合伙** → 走 `founder-friends-family`
- 用户在问**股权怎么分、薪酬** → 走 `founder-equity-split`
- 用户在问团队内部**角色怎么排、谁拍板** → 属角色（Roles）一类

## R：原文锚点

> "in my dataset of high-potential startups, only 16.1% were solo-founded, with a high of 17.5% in the technology industry and a low of 11.7% in life sciences."（Chapter Three, The Solo-versus-Team Dilemma）（已据原文核）
中译：在我的高潜创业数据集里，只有 16.1% 是单干起家；科技行业最高，17.5%；生命科学最低，11.7%。

> "A core founder might think, I know I can get along without this cofounder if I need to, so what have I got to lose? Plenty."（Chapter Three, Closing Remarks）（已据原文核）
中译：核心创始人可能会想：实在不行我一个人也转得动，那拉他进来我有什么好亏的？——亏的东西多着呢。

> "The founder has deep, relevant experience; the founder is driven to keep control of the key decisions; the industry does not demand fast growth; and the idea and its implementation are relatively simple."（Chapter Three, The Broader Context / Figure 3.3）（已据原文核）
中译：（适合单干的创始人）拥有深厚且相关的经验；有强烈意愿保住关键决策的控制权；所在行业不要求快速扩张；点子和它的落地都相对简单。

> "Underestimating the need for a cofounder heightens the risk of failure."（Chapter Three, Closing Remarks）（已据原文核）
中译：低估对联合创始人的需要，会抬高失败风险。

> "as one serial entrepreneur observed, 'Complexity increases exponentially with more cofounders.'"（Chapter Three, How Many Cofounders?）（已据原文核）
中译：正如一位连续创业者所说，"联合创始人越多，复杂度是呈指数上升的。"

## I：核心解释

1. **组队是常态，但不是默认**：高潜创业里单干只占 16.1%（科技 17.5%、生命科学 11.7%）；但"多数人都组队"不等于"你也该组队"。（R1）
2. **三资本缺口决定要不要组队**：创始人手上要有 **人力资本**（学历背后的知识 + 经验里的隐性技能）、**社会资本**（人脉与信息网络）、**金融资本**（钱与有形资源）。书里叫"基于资本的做法"（capital-based approach）：先算创业需要多少，再减掉自己已有的，看缺口——缺哪样就补哪样。
3. **缺口不一定用联合创始人补**：可以单干、后雇人（必要时）、找顾问 / 导师、外包、跟互补公司合作。
4. **还有"软"理由**：不想做某些早期任务（比如技术出身的人不想做销售）、喜欢协作式工作方式、需要支持与肯定（有创始人说"我连一个朋友都说服不了，点子能有多好？"）。这些也是真实的组队动机。
5. **什么情况该单干**（书里 Figure 3.3 的四条件）：创始人经验深厚且相关、有强烈控制偏好、行业不用快跑、点子和落地都简单。（R3）
6. **组队不是越多越好**：每加一个人都增加协调成本、拖慢速度、削弱激励；"复杂度呈指数上升"。尤其"非必要"的联合创始人还会占掉本可留给员工 / 投资人的股权。（R5）
7. **常见坑**：创始人高估自己的全能、低估缺口——"不用他也饿不死，那拉上怕什么？"（R2、R4）。

## A1：来源应用 — 书里给的具体做法

- **三资本盘点决策图**（书里 Figure 3.2 的三问）：① 我缺不缺重要的人力 / 社会 / 金融资本？② 这些能力是**创业时就需要**，还是可以以后再补？③ 我是不是宁愿一个人干？三问连起来就能落到"现在单干""现在组队""先单干、后雇人"。
- **缺口未必用联合创始人补**：先单干、后按需雇人；找有经验的顾问 / 导师先顶一阵；把部分任务外包；找互补的公司做伙伴。
- **缺口"迟到但很快会来"**：若行业跑得快、有抢跑压力（先入优势、网络效应），即便当下自给自足，也可能要一开始就拉人——因为（a）那个人不久就会需要，临时很难找到对的人；（b）选对的人能比你单干更快把公司建起来。
- **加几个 = 算边际**：书里建议对每个潜在联合创始人算"边际收益 vs 边际成本（协调 / 激励）"，只加边际收益大于成本的人；只因为你喜欢他、想有个伴，不算。
- **对"想拉个伴"的冲动设防**：非必要联合创始人会占股权、添张力，"up to a point"。

## A2：典型触发场景

- 有好点子，纠结自己干还是拉人
- 感觉"一个人扛不住"，但说不清到底缺什么
- 想拉个朋友"一起，有个伴"
- 团队已有三四个人，开始觉得决策慢、扯皮多
- 行业跑得快，犹豫要不要提前把技术 / 商务搭档拉进来

## E：执行步骤

### 步骤1：盘点三种资本与缺口

**输入**：创业需要的技能 / 人脉 / 钱 + 创始人自述已有的。**输出**：human / social / financial 三类各标"够 / 缺"。
🔴 **CHECKPOINT — 触发条件：用户只报"我会技术"就要下结论**：追问商务、销售、融资、行业知识、人脉等维度，别漏算缺口。

### 步骤2：判单干 vs 组队

**输入**：步骤1 的缺口 + 控制偏好 + 行业节奏 + 想法复杂度。**输出**：倾向"单干"还是"组队"，并按 R3 的四条件给理由。
🔴 **CHECKPOINT — 触发条件：用户"既想控制又明显缺关键资本"**：如实指出这是真两难，给两条路各自的代价，不替他选。

### 步骤3：加几个 / 何时加

**输入**：候选联合创始人清单。**输出**：每个人"边际收益 > 成本"的判断；对"缺口会迟到"的情形，给"先单干后补"或"一开始就拉"的取舍。
🔴 **CHECKPOINT — 触发条件：用户想加"只是因为喜欢 / 有个伴"**：引书里的话提醒"省心的选项长期常出事"，请他确认这人填的是哪个必要缺口。

### 步骤4：给"不拉 / 晚拉"的替代路径

**输入**：步骤1 的缺口。**输出**：顾问 / 导师、外包、后雇人、合作等替代方案（各带代价）。
🔴 **CHECKPOINT — 触发条件：替代方案落到具体股权 / 法律安排**：只提示"需要专业意见"，声明非法律 / 税务建议。

## B：边界与失败模式

### 失败模式分支表

| 情况 | 表现 | 怎么处理 |
|------|------|---------|
| 对不同人复用同一骨架 | 换个用户问同类问题，回答却是同一副开头、同一套模板 | 🛑 退回输出纪律第 1 条：先复述这一个人的具体处境，贴着它重写，删掉通用骨架 |
| 向用户抖术语 / 结构名 | 回答里冒出内部结构名或"步骤 1/2/3"（如 "三资本""四条件""边际核算"） | 🛑 删掉术语与编号，用他自己的话讲他的事（输出纪律第 4 条） |
| 只凭"想有个伴"加人 | 非必要联合创始人 | 先问填哪个必要缺口 |
| 高估自己、漏算缺口 | "我一个人能行" | 逐项盘点三资本 |
| 盲目凑人数 | 决策慢、扯皮 | 算边际成本与收益 |
| 把"先单干后雇人"当万能 | 快行业里错过窗口 | 看行业节奏与抢跑压力 |
| 越界给法律 / 股权结论 | "这样最省税" | 转专业资源，加免责 |

### 边界规则

1. 只做**结构与权衡**，不替用户决定组队还是不组队。
2. 只用书里的三资本、四条件、边际成本、缺口替代路径；自己的补充要标「（补充）」。
3. 涉法律 / 税务 / 投资：声明非专业建议，指向律师与税师。

## 📖 练习手册

**三资本清单**：写下你的创业需要哪些人力 / 社会 / 金融资本，每项标"有 / 缺"。
**边际核算**：给每个考虑中的联合创始人写一句"他填哪个必要缺口、值不值新增的协调成本"。

## 🚫 反例与黑名单

1. **因为"喜欢这个人"就拉进来** → 书里点名的陷阱，先问缺口。
2. **高估全能、无视缺口** → 逐项盘点三资本。
3. **盲目凑人数** → 算每个人的边际成本。
4. **替用户拍板** → 只给结构，选择权在用户。
5. **越界给法律 / 股权结论** → 转专业资源。

### 灰色地带（需谨慎判断）

- **用户已经拉了人、却发现对方没用**：引书里"改正一个坏联合创始人决定又难又贵"，先帮他算清缺口与退路，不代做裁人决定。
- **"先单干、后雇人"是否可行**：取决于行业快慢与缺口何时到来，不能一刀切；把两种情形的代价都摆出来。
