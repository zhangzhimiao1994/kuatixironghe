# 形势取数与映射表（相地前置）

> 相地这一支原本只能靠用户口述形势。这份文档配 `tools/xingshi.py`：**把一个地点变成一份可核对的形势描述**，交给相地类 skill 判读。
>
> **先说最重要的是什么**：取数**不等于**判读。本工具只给地理量与客观描述，**不给吉凶、不点穴、不给葬法**。把地理量对应到书里术语的那几步（下表）是**现代补充，不是原书原文**，判读必须回到 skill 的 R 节。

## 一、为什么要它

`kanyu-hub` 的 E 节把相地的输入写死为「一处具体的形势：山形来去、水从哪里来从哪里走、朝向、四周遮护」。用户往往答不上来——不是没有地，是不知道这些词对应现场看什么。取数器的作用就是**先把可测量的那部分量出来**（高程、高差、坡度坡向、八向遮护、水系方位与距离），把口述题变成选择题。

## 二、取数源与实测可用性（2026-10-08 实测，会变，取不到就照实说）

## 三、它输出什么

一段中文形势描述 + 一份原始 JSON（`--out`）：

1. **取数对象与时间**（含地名候选，供核对是不是那块地）
2. **地形网格**：中心高程、窗口内最低/最高/高差、每像素米数、取了几张瓦片
3. **中心点坡度／坡向**
4. **八方相对高差与最大仰角**（北…西北八字）
5. **由此得到的候选量**（标「（补充）」）：相对最高/最低方向、遮护最强/最弱方向
6. **水系**：半径内水体/水道数量、最近一处的类型/名称/距离/方位，附取数来源与数据时间戳
7. **交给谁**：点名相地类 skill；并重申取数不等于判读
8. **局限**：DEM 非实测、半径之外未取、OSM 乡野常缺漏、未做磁偏角校正、**不能替代现场踏勘**

## 四、映射表（**全部是「补充」，不是原书原文**）

这张表是取数器与 skill 之间的桥。左列是能算出来的地理量，右列是书里会看的词——**桥的两端性质不同，左端是测量，右端是原文概念**，所以每一步都要标明它只是「对应关系」。

| 地理量（取数得） | 书里对应的词 | 对应依据（哪本、看什么） | 可靠度 |
|---|---|---|---|
| 窗口内高差大、八方有明显高低向 | 势（远势） | 《葬書》内篇三「千尺為勢，百尺為形」「地勢原脈，山勢原骨」 | 中（只给"有势/无势"这一层，不能定名） |
| 中心点局部高差与坡度平缓 | 形止 | 《葬書》内篇三「勢來形止，是謂全氣」 | 中 |
| 沿某方向高程持续抬升 | 来势方向候选 | 《葬書》《撼龍經》论干枝来去 | 低（**方向候选，不是"来龙"定名**） |
| 沿某方向高程持续下降 | 去势方向候选 | 同上 | 低 |
| 局部高于八邻（脊）| 山之「骨」「脊」一类的候选 | 《葬書》内篇二「丘壟之骨，岡阜之支」 | 低（需现场判是不是过峡/剥换，DEM 看不出） |
| 水系距离与方位 | 「界水則止」「得水為上」的取数前提 | 《葬書》内篇二「氣乘風則散，界水則止」「風水之法，得水為上，藏風次之」 | 中（**只给水在哪、多远，不给"水口"定名**） |
| 八方最大仰角普遍偏高 | 遮护强（近于「藏風」的条件） | 《葬書》内篇二「必得城郭完密，前後左右環圍區穴，然後能藏風」 | 中 |
| 八方仰角普遍低平、无遮护 | 遮护弱（需另看横水） | 《葬書》内篇二 平支之穴「不以寬曠為嫌」 | 中 |
| 中心点附近的低洼/汇水方向 | **不给**——谷/沟是现场与水文专业判断 | 《葬經翼》一类后世书**未收进本包** | — |

**这张表明确不做的三件事**：
1. **不把「方向候选」说成「来龙」**——干龙枝龙、过峡剥换、九星形态，DEM 看不出来，只能到现场看。
2. **不把「最近水体」说成「水口」**——水口是形势上的收口处，不是几何最近点。
3. **不下吉凶**。「藏风」「得水」在书里是**条件**，不是打分项；判读由 skill 按 R 节原文做。

## 五、怎么用

```bash
# 0) 先查再跑（硬规定）：依赖 + 数据源连通；有不可用项就停下，不许跑到一半才发现取不到
python tools/install_deps.py            # 含数据源连通探针（有不可用项退出码非 0）
python tools/xingshi.py --check         # 只体检、不取数

# 1) 分享链接（最省事：地图 App 里「分享 → 复制链接」直接丢进来）
python tools/xingshi.py --url "https://surl.amap.com/xxxx" --radius 3
#   高德(surl.amap.com)/百度(j.map.baidu.com)都认；自动解坐标+地名，并按 GCJ-02 / BD-09 转 WGS-84

# 2) 地名（会列候选，核对后 --pick N；拿不准就别用这条）
python tools/xingshi.py --place 江西婺源 --radius 1.5 --out xingshi.json

# 3) 直接给经纬度（最准），并说明是哪家地图读的
python tools/xingshi.py --lat 28.4546 --lon 117.9686 --crs wgs84 --radius 3
python tools/xingshi.py --lat 28.4513 --lon 117.9736 --crs gcj02 --radius 3   # 高德/腾讯/微信
python tools/xingshi.py --lat 28.4575 --lon 117.9801 --crs bd09  --radius 3   # 百度

# 4) 区域大势粗读（区域倾斜方向 + 高带/低带方位；建议 15–40 km）
python tools/xingshi.py --url "https://surl.amap.com/xxxx" --area 30

# 5) 依赖（走国内源，一次装完）
python tools/install_deps.py --install
```

**经纬度必须先说清是哪家地图读的**：高德/腾讯/微信是 GCJ-02、百度是 BD-09，跟 GPS/OSM 的 WGS-84 差 **100–1200 m**（实测高德 609 m、百度 1169 m）。本包取数源一律吃 WGS-84，`--crs` 会自动转，转了多少米会打出来给你看。**写反经纬度的会被拦下报错**，不会静默算错。

`tools/xingshi.py` 运行时会**自动先做一次 pre-flight**：三个数据源有任何一个不可用，它**不开始取数**，直接停下并逐源写明原因（可选 `--force` 带着缺项跑，失败项会在输出里照实写明）。声明的依赖见它在 skill frontmatter 里的 `requires:`（`pip` / `commands` / `data`）。

拿到输出后按这句话接下去：**描述 → 相地类 skill（藏风得水／支垄之辨／势来形止／形势品类／疑龙经下篇／倒杖十二法）→ 该 skill 按自己的 R 节判读**。取数里标了「（补充）」的量，在回答里也要保留这个标注。

## 六、已知局限（写给使用者）

- DEM 是公开 30m 级数据，**不是实测**；城郊/林地可能有偏差，陡崖与人工改造处误差更大。
- 窗口默认半径 2 km（可调），**窗口之外没取**；名山巨镇的"大势"远超这个尺度。
- OSM 水系在乡野**常有缺漏**——「取到 0 条」不等于现场无水，只表示数据里没有。
- 方位以**真北**为准，**未做磁偏角校正**（书里的罗盘口径另有讲究，两者不要混着说）。
- **最要紧的一条**：本工具与三维度都**不接阴宅实地作业指导**。隔着数据和文字点穴，就是编。
