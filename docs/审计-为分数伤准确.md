# 审计：有没有 skill「为了分数而伤准确」

**问题**（维护者）：检查所有 skill，有没有**为了单纯提高分数**而**影响准确/正确性**的。

**方法**：对全包 309 个 skill 扫 8 类可测特征（引书合规式硬要求／无出处的自证／凑数引文／空洞检查点／过度模糊／堆安全语／跨 skill 重复长句／过短条目），命中处再**读原文**判定。

## 结论

**没有找到「为了让尺子给高分而把判断写歪、写模糊、写硬」的证据。** 扫出的真问题只有一类：**为过结构检查而留下的模板壳**，且全部来自 **2026-10-06 那一批**生成后未清理。

## 真问题的内容与改法

1. **`## 审计信息` 节（23 个）**——模板残留，三行全是自证：`验证通过: V1 ✓/V2 ✓/V3 ✓`、`测试通过率: {{%}}`（另 5 个写「待定」）、`蒸馏时间: {{DATE}}`（另 5 个写 `2026-04-18`，模板默认值）。**一旦没填就是虚报「跑过测试」**。→ **删整节**（其余 280 个 skill 都没有这一节）。
2. **模板 CHECKPOINT（25 个）**——一律挂第 2 步末尾：`🔴 CHECKPOINT: 在进入下一步之前，将分析结果展示给用户，等待确认后再继续。`（半角冒号＝模板原文），对任何 skill 都成立＝没有检查。
   - 其中 **22 个**：另有自己带判据的检查点 → **删模板那条**
   - 其中 **3 个**（relationship-assembly／response-action／reversal-cycle）：步骤里已自带「完成标准」→ **删**（模板那条纯冗余）
   - 其中 **5 个**（body-mind-integration／communicate-persuade／excess-deficiency-decision／observe-infer／personalize-by-constitution）：**模板那条是唯一检查点** → **就地转成真判据**（按各 skill 第 2 步自己的输出格式写），不减反增。
3. **同句式空洞检查点（10 处）**——「展示 X，等待确认。」无判据 → 按各 skill 第 2 步的输出格式**补成真判据**：advance-retreat-boundary／auspicious-risk-language／bottleneck-unblock／conflict-coalition-diagnosis／four-seas-regulation／hexagram-situation-diagnosis／humility-overreach-check。

## 没做的、和为什么

- **不给 205 个旧成员铺「必须补出处」**：按取舍优先级（好用 ＞ 准确 ＞ 分数），那是**引书合规**，伤好用、不治准确。
- **不把「短检查点」一律当空洞**：约 30 处短检查点其实是合格的（如 `bazi-hub`「这里只报算出来的量、不夹判读」、`cross-system-hub`「确认已标注所有 ≥3 体系共振点」）——**短是因为它本来就短**。
