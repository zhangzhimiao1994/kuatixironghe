## 二、R 节硬规矩

1. **每条必须是原书原话，逐字**。异体字、异文照抄（如「㑹／會」「㣲／微」「𦵏」「殺／煞」「財／才」在同一本里混用，照原样），不改写成今字，不动标点。
2. **经文与注要分栏**：滴天髓闡微的正文是经文，〈…〉或「原注／任注」是任鐵樵注——两者都要标清是「經文」还是「注」。
3. **不许把后世术家的说法冒充原书**：书里没有的做法（尤其现代命理流派的「喜用神」「调候用神」之外的术语、各种「指数」「打分」），写「（补充）」，并说明依据。
4. **一条 skill 的 R 节至少 3 条引文**；少于 3 条说明这个主题在原书里撑不起来，回去并到邻近 skill。
5. **回书核**：写完用归一化（只留字形，忽略空白与标点差异）比对源文件；核不过的删掉或改掉，不许强留。

## 三、判读口径

1. **象征层只命名、不承诺**：八字讲的是「干支之象」——一律写「倾向 / 按书里这一类读」，不写「一定 / 必然 / 命中 / 保证发财发贵 / 注定」。
   原书里的断语（「大貴」「貧夭」「克夫」「無子」这类）属于**书里的评价语**，引用时要标明是书里的说法，不当作对某人的事实判决。
2. **不接的活**：**不批流年大运、不断终身、不判生死寿夭、不替用户做婚姻/职业/医疗决定**；不给医疗、法律、投资结论；不替用户拍板。
   **尤其**：不得依据八字给出疾病诊断、寿命预测、生育判断——书里有这类条文，引用时可标为「书里的说法」，但**不许落到具体的人身上**。
3. **落盘读法（这一族的主活）**：拿到四柱后，按书里的取用条件**逐项核，再给读法层面的倾向**。四步：
   ① **输入**：用户的四柱（或已排好的盘）＋ 本 skill 的条件；
   ② **逐条核条件**：书里要求什么（几位、透还是藏、有破无破、月令可不可取），这盘满足到哪一步；
   ③ **输出**：一句「按书里这一类读，偏 X」＋ **出处**（卷次／篇目）；
   ④ **收口**：不应期、不断终身、不落寿夭疾病生育、不替人决定。
   **可以做**：月令取何神、某格条件满足到什么程度、调候先取哪一味、十神分布偏在哪。
   **不可以做**：应期（哪年发生）、终身断语（一生一句定）、生死寿夭疾病生育、替用户做婚姻职业医疗决定。
4. **两种问法并存**（判据：**输入里有没有四柱或出生信息**）：
   - 问「**书里这句什么意思／这一篇专门讲什么**」→ 走**文本解读**（认句归篇、摆条件），不必落盘；
   - 问「**我这盘怎么看**」→ 走**落盘读法**（上一条）。
   没给四柱就默认文本解读，并补一句「给我四柱就能照书读一遍」；给了四柱而用户只问出处，也按文本解读答，不硬塞落盘。
5. **四本并陈、不替它们调停**：同一问题各家说法不同时（子平真詮以「用神＝月令、格局论成败」立说，其篇 29–30 反对「拘泥格局、以讹传讹」，与三命通會那一路有对着说的地方）——**两说都展示、各标出处**，必要处直说「这一处两家不同」，**不选边、不合成一句话**。跨体系分析的本事在呈现张力，不在消解张力。
6. **女命篇的评价语另加一道闸**：可以落盘读「夫星在哪、取用条件满足到什么程度」；但「克夫」「賤」「淫」这类**只可念、不可落到人身上**。
7. **数据不足照实说**：缺出生年/月/日/时任一柱、或缺出生地（真太阳时用），就说缺什么、要到什么程度才能排，**不许用占位信息硬排**；出生时刻只到时段（如「辰时」）时，时柱按该时段整体给出，并标明「时段内不唯一」。
8. **术语照写、简称不给**：维度名、权重、危机层级、STEP 编号照写；自造的方法零件名（「两栏」「三问」这类）不进正文。
9. **报格局/用神必须给全两句**：断一个格局或用神，必须同时给出**原书依据（哪一本、卷次/篇名）**与**取用条件（凭什么这么取）**；只报格名不出处 = 不合格。
10. **工具与判读分开**：`tools/bazi.py` 只做**可核的历法与规则计算**（四柱、藏干、十神、五行计数）；**旺衰、格局、用神、吉凶属判读**，必须回到原书条文上，不许拿工具的输出当结论。

## 四、骨架（缺一不可，`tools/dim_check.py` 会逐项查）

- frontmatter 四字段：`name` / `description` / `input_schema`（`required`+`optional`）/ `output_schema`（`primary`+`secondary`）。
- 正文十节：`## 触发条件` / `## R：原文锚点` / `## I：核心解释` / `## A1：来源应用` / `## A2：典型触发场景` / `## E：执行步骤` / `## B：边界与失败模式` / `## 练习手册` / `## 反例黑名单` / `## 灰色地带`。
- `test-prompts.json`：三类用例 `should_trigger` / `should_not_trigger` / `boundary`（可写成 `boundary_cases`，自检认得）。
- 入口 `bazi-hub` 的触发条件**开头必须写硬闸门**（见 `distill/bazi/PLAN.md` 第六节）。

## 五、不许出现的东西

- 任何 agent / 工具 / 模型 / 运行时的专有名词；路径一律写包内相对路径。
- 现代科学名词去解释原书（如拿「统计」「概率」给「格局」背书）；也**不许**用现代命理流派的说法（如各种「旺衰计分表」「喜用神自动判法」）冒充古法。
- 把八字写成「迷信」的自我否定腔，也写成「灵验」「准得可怕」的兜售腔。
- 抄别族 skill 的正文；本族内部也不互相复制段落。
